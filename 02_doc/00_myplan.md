但更好的做法是不要求搬车：让用户在地图上点一下"车在这里"，发 /initialpose 设初始位姿——这是 nav2 的标准做法，体验好得多。

我的理解是这样的：  就是假如小车当前所在的位置，不在建图起点，而在地图中的某一点；如果小车进入到导航模式，程序会默认小车所在位置是建图起点，而导致位置错乱。

而让用户在地图上点一下"车在这里"，然后小车程序中使用/initialpose 设初始位姿，告诉程序，小车的位置不在原点，而在地图中的某一点。给出初始猜测，之后激光持续修正, 还要给朝向，不只是位置,偏差大时会锁死（slam 是局部优化，不像 AMCL 能全局重定位）

# 手机 UI 模式化改造 · 需求清单

## 一、总体原则

| 编号 | 需求 | 验收标准 |
|---|---|---|
| R1 | 手机 UI 新增**首页**，作为模式入口 | 打开网页首屏即首页，可见四种模式入口 |
| R2 | 四种模式：**建图 / 导航 / 编辑地图 / 探索** | 首页四选一，选中后进入对应工作流 |
| R3 | **页面与模式分层**：页面（遥控/航点/巡逻/探索/编辑/语音/功能）是"看什么"，模式是"车在干什么" | 同一模式下可切换页面；模式状态全局可见 |
| R4 | 模式互斥由 `ModeMgr` 统一仲裁，不允许两个模式同时持有控制权 | 任一时刻只有一个模式为激活态 |

## 二、初始位姿（替代"搬车回原点"）

| 编号 | 需求 | 验收标准 |
|---|---|---|
| R5 | 进入**导航模式**时，提示用户设定初始位姿 | 进入导航模式后出现明确提示 |
| R6 | **不强制搬车**。支持在地图上点一下"车在这里"，发 `/initialpose` 设初始位姿 | 车停在任意位置，点图设位姿后红三角跳到该点 |
| R7 | 初始位姿必须包含**位置 + 朝向**（不只是位置） | 点两下：第 1 下定位置，第 2 下定方向（沿两点连线） |
| R8 | 初始位姿是"初始猜测"，之后由激光 scan matching 持续修正 | 设置后 1~2 s 内红三角与实际位置对齐 |
| R9 | 设置初始位姿后给出反馈（成功/失败、当前定位状态） | 页面显示"定位已对齐"或"定位不准，请重设" |
| R10 | 初始位姿功能**随时可用**（不限于启动时），用于纠正定位漂移 | 导航运行中可重新设位姿，不需重启 |

> **消息类型**：`geometry_msgs/msg/PoseWithCovarianceStamped`（**不是** `PoseStamped`）
> **已验证**：`slam_toolbox` 订阅 `/initialpose`，N1 真机实测通过；无其他节点抢占

## 八、已验证的技术事实（实施依据）

1. `slam_toolbox` **订阅** `/initialpose`（`slam_toolbox_localization.cpp`）—— N1 真机实测通过
2. 消息类型 `geometry_msgs/msg/PoseWithCovarianceStamped`；`covariance` 不要给 0（建议位置 0.25 / 朝向 0.07）
3. `map_start_pose: [0.0, 0.0, 0.0]` 要的是**建图起点**，与地图 `origin: [-4.69, -13.14]` **相差十几米**，别混淆
4. 偏差小（几十厘米 / 十几度）scan matching 会自己收敛；偏差大可能**锁死**（slam 是局部优化，无全局重定位）
5. `/initialpose` 无其他节点抢占（全仓库无代码发此话题）；`ros2 topic info -v` 显示 `nav2_goal_bridge` 是发布者属 **CLI 归属错误**（与已知的 `_NODE_NAME_UNKNOWN_`、"7 个僵尸发布者"同类）
