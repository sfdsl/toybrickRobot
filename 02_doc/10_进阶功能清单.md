# 进阶功能清单（自主导航之外还能做什么）

用途：这条 SLAM 小车除「自主导航（《08_自主导航实验方案.md》）」之外的**可选功能池**——
按投产比排序，每项写了做法、依赖、验收判据与代码接口点；挑做 / 答辩写"未来工作"都能直接用。
制定日期：2026-09-20

---

## 0. 家底核查（2026-09-20 实测，决定哪些能做）

| 资源 | 状态 |
|---|---|
| 算力 | RK3588 八核；**NPU 运行时在位**（`/usr/lib/librknnrt.so`、`librknnrt_rk356x.so`） |
| AI 例程 | **`/data/aidemo`** 在（含 yolov5s / yolov11 等 RKNN 官方例程） |
| 相机 | USB UVC（`/dev/video0` 与 `video1` 是**同一台**相机，`/dev/media0`）——**无深度** → 只能做 2D 视觉 |
| 雷达 / 底盘 | LD14P 6 Hz 360°（实测最远回波 10.45 m）；麦轮底盘 + 编码器里程计（已标定 3645 / 0.4085） |
| IMU | 电源板 I2C（±2g / ±250 dps，见《08》N6；待接） |
| 人机交互硬件 | 电源板自带 **TFT 屏 + RGB LED + 按键**（`sd_power/` 驱动齐全） |
| 软件栈 | ROS 2 Foxy（**无 apt 源**，缺包只能源码编）；rosbag2 齐全；**无 `usb_cam` / `image_transport`** → 相机进 ROS 需自写约 20 行 |
| 现有工具 | `robot` 一键启动、`phone` 手机网页（遥控 + 地图 + 保存地图）、`drive` 自动行驶、`savemap` → `04_map/`、`mapv` / `scanview` |

**已实现**：建图（04 S1~S6）、手机遥控/看图/存档、自动行驶建图、`/map` 1 Hz、地图四件套（时间戳）
**进行中**：自主导航（08：定位模式 + A* + 纯跟踪 + `/goal_pose`）、IMU 接入（08 N6）

## 一、第一梯队（每项 0.5~2 天，几乎全复用现有代码）

### A1 手机点图导航 ★
- **做什么**：在手机地图上点任意位置 → 车自动开过去（可带朝向）
- **怎么做**：`phone_teleop.py` 的 MJPEG 画面上加点击事件 → 像素坐标按 resolution/origin/视窗范围换算成地图坐标 → 发 `/goal_pose`
- **依赖**：导航（08）+ 手机网页（已有）
- **验收**：点房间对角，3/3 到达，终点误差 <0.15 m
- **接口点**：`phone_teleop.py`（PAGE 的 JS + 新增 `/goal` 端点）、`goal_nav.py`

### A2 多点巡逻 / 巡检
- **做什么**：按顺序循环走 N 个点，每点停 3 s（可选播报"已到达 X"）
- **怎么做**：航点列表（JSON，与地图同目录）→ 依次调用单点导航；`--loop` 循环
- **验收**：3 点巡航 2 圈不中断；中途 Ctrl-C 安全停车
- **接口点**：`goal_nav.py` 的"单点导航"函数 + 航点文件

### A3 语义 / 标注地图
- **做什么**：地图上标点命名（门口 / 货架 / 充电位）→ 存 `04_map/<地图名>.places.json`；支持"导航到 门口"
- **怎么做**：复用 A1 的点图机制 + 弹窗输入名字；导航时按名字取坐标
- **验收**：标注 3 个点，按名字导航成功
- **接口点**：A1 的点图机制、`goal_nav.py`、`04_map/` 目录约定

### A4 地图编辑器（清理 + 虚拟墙）
- **做什么**：擦掉误判障碍（玻璃/反光造成的假墙）、画禁行区 → 生成 `*_clean.pgm` 给导航用
- **怎么做**：OpenCV 画布（鼠标涂改）或手机网页点涂；另存新 PGM/YAML（不改原始档）
- **验收**：清理后不再撞"假障碍"；虚拟墙被规划器尊重
- **接口点**：`04_map/` 的 PGM/YAML、导航的可通行/膨胀判定

### A5 视觉识别接入（RKNN + NPU）★
- **做什么**：`/detections` 话题（类别/置信度/框）+ 手机页面叠加"看到了什么"
- **怎么做**：① 相机→ROS：自写约 20 行（cv2 → `sensor_msgs/Image`，因为无 `usb_cam`）
  ② 推理：用 `/data/aidemo` 的 RKNN 例程（走 NPU）
  ③ 发布：无 `vision_msgs` 则自定义 msg（或直接用 `Float32MultiArray` 简化）
- **依赖**：例程与 NPU 运行时**均已就位**
- **验收**：yolov5s 常见目标可识别，≥10 FPS（RK3588 NPU 上通常远高于此）
- **接口点**：新建 `01_Project/04_Vision/`（或 ros2_ws 新包）、手机网页 HUD

### A6 语音指令 + 到点播报（零依赖）
- **做什么**：手机浏览器说"去门口 / 停" → 调网页接口；到达用 TTS 播报
- **怎么做**：浏览器 `webkitSpeechRecognition` + `speechSynthesis`，只改 `phone_teleop.py` 的页面 JS
- **验收**：安静环境下常用指令可用；**误识别有「停 止」按钮兜底**
- **注意**：Android/Chrome 支持较好，iOS Safari 部分支持 → 页面里做降级提示

### A7 rosbag 录制 / 回放
- **做什么**：一键录 `/scan /odom /tf /cmd_vel`（可选 `/map`）→ 复盘与参数对照（如"开不开 IMU"）
- **怎么做**：`ros2 bag record -o ~/RobotCode/logs/bags/<时间>`；给 `start_robot.sh` 加 `--bag` 开关
- **验收**：录 2 分钟能回放；能用回放复现一次定位异常

### A8 状态灯 / 屏 / 按键（用上电源板）
- **做什么**：RGB LED = 待机(蓝)/建图(绿)/导航(黄)/故障(红)；TFT 显示 IP、电量、状态；按键 = 急停或启动
- **怎么做**：把 `sd_power/` 的 `key_led`、`tft` 驱动封成一个小节点（或独立进程），订阅 ROS 状态
- **注意**：i2c/SPI 权限（照 IMU 的 udev 思路）；TFT 与 `sd_power/sample` 会互相抢
- **验收**：状态切换灯色正确；TFT ≥1 Hz 刷新

### A9 电量 + 温度监控
- **做什么**：`/battery`（电压/百分比）+ 网页显示 + 低电提醒（可选：自动返航）
- **怎么做**：底盘协议 `AT+BATTERY?`（已实测可用）→ `base_driver` 增加发布；IMU 温度当板温参考
- **验收**：与万用表比对误差 <5%；低于阈值能提醒

## 二、第二梯队（每项 2~5 天，真正的"高级功能"）

### B1 自主探索建图（frontier exploration）★最推荐
- **做什么**：给个起点，车自己找"已知-未知边界"逐个探索，直到没有明显灰区或到时 → 自动保存地图
- **怎么做**：从 `/map` 提 frontier（空闲-未知边界，CV + 聚类）→ 选最优目标 → 复用导航（08）→ 循环；终止条件用"未知占比 <X%"
- **依赖**：导航（08）
- **验收**：单/多个房间全探索，自动存 `explore_<时间>` 四件套，全程无人干预
- **价值**：把"建图"与"导航"合体，是答辩最有说服力的一项

### B2 动态避障 / 局部重规划
- **做什么**：路径上出现新障碍（人、被挪动的椅子）→ 减速绕行或停车等待，再重规划
- **怎么做**：全局 A* + 滚动窗口局部代价（简化 DWA：采样速度打分）+ `/scan` 实时膨胀；规划失效即重规划
- **验收**：人从车前走过不撞、能绕或等；地图局部更新后路径随之更新

### B3 目标跟随
- **做什么**：锁定一个人/物体，保持 1~1.5 m 跟随
- **怎么做**：① 视觉路线：A5 检人 + 用框宽估距离（无深度） ② 纯激光路线：聚类最近移动点团，跟随其质心
- **验收**：绕一圈能跟住；目标丢失 >3 s 自动停车

### B4 ArUco / 二维码精确停靠
- **做什么**：识别墙面/地面标记 → ±2 cm 级精确停位（充电桩、货架对接的基础）
- **怎么做**：`cv2.aruco`（OpenCV 自带，零新依赖）→ 相机内参标定（打印棋盘格，十分钟）→ 视觉伺服微调
- **验收**：正对标记 0.5 m 处停靠，横向误差 <3 cm

### B5 自动回充
- **做什么**：低电或收到指令 → 回充电桩 → 对准 → 对接
- **怎么做**：B4 的标记停靠 + 桩端接触（触点/磁吸）；桩可 3D 打印或亚克力自制
- **依赖**：**需要硬件（充电桩）**；先完成 B4
- **验收**：连续 5 次对接成功并建立充电电流

### B6 语义地图（识别结果上图）
- **做什么**：把 A5 的识别结果投影到地图格子 → "这里有一把椅子/一个箱子"
- **怎么做**：相机-雷达外参标定（已有 `camera_lidar_view.py` 的融合基础）→ 目标地图坐标估计 → 存成地图旁边的标注图层
- **验收**：挪动一个箱子，图上标注位置与实际误差 <0.3 m

## 三、第三梯队（进阶 / 需要额外硬件）

| # | 功能 | 需要什么 | 验收 |
|---|---|---|---|
| C1 | 伪 3D 建图 | 给 LD14P 加小舵机做俯仰扫描（或用深度相机） | 拼出点云，能看出门框/桌子高度层次 |
| C2 | 外网远程监控 | 内网穿透（frp/nps）或 MQTT 上云 | 4G 网络下能看实时地图并下发目标点 |
| C3 | 多机协同 / 地图共享 | 第二台车 | 两车同场不互撞、地图可合并 |
| C4 | lifelong 多日累积建图 | 无（包内已有 `mapper_params_lifelong.yaml`） | 同一场地连跑 3 天，图精化但结构稳定、无重影 |
| C5 | 仿真回归测试 | 把联调用的"假底盘"扩成轻量 2D 仿真（激光 raycast，不用 Gazebo） | 同参数下仿真与真车到点误差差 <30% |

## 四、建议的推进顺序（投产比优先）

1. **导航（08）** → 顺手白得 **A1 手机点图**、**A2 多点巡逻**
2. **A5 RKNN 视觉**（例程与 NPU 都现成，缺的只有"相机进 ROS"那 20 行）
3. **B1 自主探索建图**（建图 + 导航合体，最亮）
4. **A6 语音** + **A3 语义地图**（"能交互" + "能理解环境"）
5. 冲精度再上 **B4 ArUco** / **B5 回充**；炫技上 **C1 伪 3D**

## 五、答辩叙事线

> 能建图 → 能导航（任意点）→ 能理解环境（识别 + 语义）→ 能自主探索（无需指定目标）
> → 能与人交互（手机点图 / 语音）→ 能长期运行（电量监控 / 回充 / lifelong）

每加一层都是"智能化等级"的提升，比单纯堆功能更有说服力。

## 六、维护约定（新增功能都照这个来）

- 一个功能一个可执行/脚本，放 `01_Project/` 对应目录；快捷别名进 `~/.bash_aliases`
- 新产出的数据（地图 / 航点 / 标注 / rosbag）统一放 `~/RobotCode/04_map/` 或 `~/RobotCode/logs/`
- 每做完一项，在《05_实验记录与结论.md》追加一条实验（编号顺延），并更新《09_使用说明.md》与速查卡
- 涉及新依赖时先查《01_环境问题清单.md》的"P0-3 功能包残缺"——本机**无 ROS apt 源**，缺包只能源码编，优先选零依赖实现
