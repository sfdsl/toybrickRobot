## 2. 实验 8：drive spin 转角复验（P24，已闭环 ✅）

**发现**：`drive spin` 真机转满一圈不自停，`/odom` Δyaw（wrap 后）= −1.8°。

**排查**：
- /odom 转角积分本身**准确**：转 360° 回绕到 0、残差 1.8° = **0.5% 精度**
  → 9/18 实验 3 的 `wheel_separation=0.4085` 标定依然有效，无需重标
- 不自停的根因在 `auto_drive.py turn()`：末端减速下限
  `w = max(0.12, 2.0*err)` —— err < 0.06 rad 后 ω 指令 **0.12 rad/s 落进底盘死区
  （≈0.15 rad/s，见 08 方案 §9.2 P9）** → 最后 ~3° 永远转不完

**修复（P24）**：
- 减速下限 0.12 → **0.18**（过冲 ≤0.5°/周期，1~2 周期收敛）
- 顺带修 Ctrl-C 时 `rclpy.shutdown()` 双重调用的 RCLError traceback

**复验（同日）**：`drive spin` → **359.7° 自停，用时 15.3 s**（理论 15.7 s，效率 ~97%），
残差 0.3° = **0.08%**。修复闭环 ✅

**结论**：轮式 /odom 短时航向精度 0.08%/圈，非常好。
→ **IMU/EKF 的预期收益进一步下调**：只剩"长时漂移"与"打滑场景"两个用途。

## 3. 实验 9：到达误差首次量化（errexp 工具，✅）

**新工具**：`01_Project/03_SLAM/err_exp.py`（别名 `errexp <x> <y>`）——
读 `/tmp/rec_live.log` 最后位姿 vs 目标坐标，输出到达误差与判据。
（记录器 `odom_rec.py` 已固化并挂进 `robotnav`，`robotstop` 会收它。）

**首测**：目标 (4.27, −0.12) → 终点 (4.140, −0.250)，**误差 0.184 m**（当前判据 ≤0.20 ✅）。

**过程暴露问题**：日志显示车在 **(3.29, −0.10) 附近磨蹭**：
```
775s  (3.29, −0.10) v=(0.017, 0.067)
1465s (3.32, −0.08) v=(0.010, 0.062)
```
`v` 和 `ω` **双双低于底盘死区**（v 半速档、ω 0.15）→ 底盘几乎不动 → 磨十几秒。
这是 MPPI"慢速更便宜"（轨迹点少踩膨胀代价）的解滑进死区——P19 关闭
`VelocityDeadbandCritic` 的副作用回归。

## 4. 实验 10：P25 死区 critic 重开 + 蛇行暴露（✅ 磨蹭已修，⚠ 摆头新发现）

**P25**：重新启用 `VelocityDeadbandCritic`（deadband `[0.04, 0.0, 0.17]`）。
P19 的摆头主因（`regenerate_noises=True` 每周期重抽噪声）此前已修，理论不复现摆头。

**验证跑**（目标 4.22, −0.04）：
- 磨蹭消失 ✅（全程无 0.01~0.02 爬行段）
- 到达误差 **0.054 m** ✅（远优于 0.15 判据）
- 转向输出果断（出现 0.4~0.8 rad/s，不再落死区）✅

**新发现——全程蛇形摆头**：日志 ω 在 ±0.8 间大幅摆动（0.65 → −0.60 → 0.63 → −0.8 …），
位置画 S 形（y 在 ±0.25 m 间振荡，周期 5~8 s），用户观感"遇到障碍后瞎摆头"。

**三来源分析**：
1. `velocity_smoother` ω 加速 **3.0**（P17 为 DWB 提的）把相邻周期解跳变原样放大给底盘；
   减速 ω 仅 −1.0，转向要停时收不住 → 过冲 → 反向修正 → 摆
2. `wz_std 0.25` 采样噪声仍偏大 → 相邻周期"左绕/右绕"最优解跳变
3. `repulsion_weight 0.7` 两侧对称排斥随雷达点（6 Hz）跳动 → 中线不是稳定极小值

## 5. P26 / P27 抗摆头修改（P26 ✅ 已验证；P27 **待验证**）

### P26 结果（✅ 磨蹭消失、精度提升，⚠ 摆头仍在）

| 验证项 | 结果 |
|---|---|
| 到达误差 | **0.050 m**（目标 4.32,−0.05 → 终点 4.28,−0.08），连续两次 0.05 级 |
| 磨蹭 | 消失 ✅（无 0.01~0.02 爬行段，死区 critic 生效） |
| 摆头 | ⚠ 仍在：yaw ±60° 来回甩、位置 S 形 |

**P26 后日志实锤摆头元凶**：大量 `v=(0.000, ±0.8)` —— **v=0 纯转 + ω 恰为满幅 0.8 = RotationShim 指纹**。机制（正反馈）：
BT 每 1 s 重规划 → 蛇行中车头与新路径起始方向差 >45° → shim 介入猛转 0.8 → 过冲 → 车头又偏 → 下一帧再介入。

### P27 修改（部分生效——摆幅下降但 shim 冲突仍在）

P27 结果：shim 满幅 ω=0.8 指纹消失（降到 0.35）、ω 幅度整体下降，但 **`v=(0.000, ±0.35)`
的 shim 纯转指纹仍频繁出现**——60° 门槛没拦住，因为 BT 每 1 s 重规划路径，车头与新路径
起始方向反复差超 60°。**shim 与"每秒重规划"结构性冲突，降参数无解。**

### P28 修改（**已编译，待验证**）：移除 rotation shim

| 项 | 修改 | 理由 |
|---|---|---|
| `FollowPath` | RotationShim+MPPI → **纯 MPPI** | 大偏差交给 MPPI 自己（DiffDrive 原生支持原地转；PreferForward 已 2.0——P21 加 shim 时还没有这个条件） |

**风险与回退**：P21 的回程窄口徘徊可能复发（shim 当初就是为它加的）。
回退方法：恢复 `plugin: "nav2_rotation_shim_controller::RotationShimController"` +
`primary_controller: "nav2_mppi_controller::MPPIController"` + shim 四参数
（threshold 1.4 / rotate 0.35，即"更大偏差才介入、介入也更温和"的组合）。

**验证方法**：
```bash
robotstop && robotnav --nav2
tail -f /tmp/rec_live.log      # 边跑边看
errexp <目标x> <目标y>          # 到达后量化
```

**判定分支（本轮重点测：正向 + 回程，各一次）**：
- ✓ 正向不摆头、**回程也不徘徊** → P28 定版（最理想），进"接下来"第 2 项
- ⚠ 正向好、回程徘徊 → 恢复 shim（threshold 1.4 / rotate 0.35 的温和版）
- ⚠ 出现新的原地打转 → PreferForward 2.0 → 3.0 回调

### P30 验证 + P32（2026-09-23）——ignore 归零带成为新死锁边界

- 其余好消息：蛇形未复发（P29 回退定版）、恢复三数字全部吻合

**P32 修复（ignore 阈值下调）**：

| 参数 | 原值 | 新值 | 理由 |
|---|---|---|---|
| `wz_ignore` | 0.03 | **0.015** | 45° 对准只需 ω=0.02 起步（boost ~10°/s，5 s 完成）；0.015 以下才算收敛噪音 |
