## 1. 项目目标与范围

### 1.1 项目目标

把手机 UI 从「功能平铺的六个页面」升级为「**模式驱动**的工作流」，并补齐两个长期痛点：

1. **定位初始化**：取消"搬车回建图起点"，改为**地图点选设初始位姿**（位置 + 朝向）
2. **多图管理**：可在导航 / 编辑模式中**选择不同地图版本**（编辑版 / 探索版 / 不同时期建的图）

### 1.2 范围界定

| In Scope（本期做） | Out of Scope（本期不做） |
|---|---|
| R1~R23 全部功能 | R24 语音导航（依赖 P3，仅留入口位） |
| N1 地图清理、N2 元数据、N3 命名消歧 | 地图**热切换**（N4 已判定不可行） |
| 前端新页面 + 后端接口 + 启动脚本改造 | 地点**自动迁移**（换图后旧地点仍失效，仅做提示 N5） |
| 离线自测 + 实车验收 | 多机协同、外网访问、App 封装 |

### 1.3 不做什么（明确排除，避免范围蔓延）

- **不改** nav2 规划/控制参数（P35~P37 的成果保留）
- **不改** P1 统一控制链（`control_mux` / `control_policy` / `ModeMgr` 的仲裁语义）
- **不引入** 新第三方依赖（无新 apt 包、无新 Python 库）
- **不重构** slam_toolbox 定位方案（保持 posegraph 路线）

| **T1.5** | 离线自测：合成地图 + 假 TF，验证朝向四元数换算与协方差 | `_selftest_pose.py` | T1.1 | 0.25d | 自测全过 |

**技术要点**
- 消息类型：`geometry_msgs/msg/PoseWithCovarianceStamped`（**不是** `PoseStamped`）
- 朝向四元数：`z = sin(θ/2)`、`w = cos(θ/2)`
- 该功能**随时可用**（R10），不限于进入导航模式时

## 8. 发布与回滚

### 8.1 发布流程

1. **开发完成** → 全部 `_selftest_*` 通过
2. **离线集成** → `robot --mode mapping --nav2` 跑通，六屏无 JS 报错
3. **实车验收** → §7.2 矩阵 100%
4. **文档同步** → `09_使用说明.md` / `00_myplan.md` / `17_路线图.md`
5. **归档** → 本清单回填完成状态

### 8.2 回滚预案

| 场景 | 回滚动作 | 影响 |
|---|---|---|
| 新首页/模式出问题 | 保留旧 tab 导航；`home.html` 改为可选入口 | 零影响 |
| `/pose/set` 出问题 | 停用该入口；保留 `ros2 topic pub /initialpose` 手动命令 | 可用命令行兜底 |
| 换图功能出问题 | 回到"手工改 `mapper_params_localization.yaml` + 重启" | 退回现状 |
| 编辑/探索整合出问题 | 各屏独立可用，互不影响 | 可逐项回退 |
| **整体回退** | `git` 回退 + `robotstop` 重启 | 全部回到改造前 |

## 附：与现有架构的衔接要点

1. **不动 P1 统一控制链**：新功能的运动控制一律走 `/task/request` 或 `/stop`，不直发 `/cmd_vel`
2. **复用 `ModeMgr`**：模式互斥不新建机制，`MAPPING`/`NAVIGATING`/`EDITING` 作为新模式值接入
3. **复用 SSE `/events`**：新页面状态走现有 `state()` 扩展，不新增高频轮询
4. **复用六屏 UI 风格**：`home.html` 沿用 `common.css`/`sub.css` 的深色仪表盘语言，不引入框架
5. **地图坐标系一致性**：所有地图操作保留 `origin`/`resolution`，换图后 `map_id` 变化必须显式提示
