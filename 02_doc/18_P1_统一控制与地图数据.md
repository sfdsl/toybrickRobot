# P1 统一控制与地图数据：实现与验收

## 启用

代码已更新并构建。**当前仍运行的旧 `robotnav` 进程未重启**，因此速度仲裁、电量话题和新 HTTP 接口要在下次启动 `robotnav --nav2 --vision` 后才生效。启动后先确认 `/cmd_vel_nav`、`/cmd_vel_manual` 只有 `control_mux` 汇入 `/cmd_vel_muxed`，再由 `collision_monitor` 发布 `/cmd_vel`。启动脚本的 `--bag` 可同时录制控制命令、三个速度阶段、电量及定位话题。

## 控制入口

网页遥控和旧 `phone_teleop.py` 在 Nav2 模式下发布 `/cmd_vel_manual`；Nav2 继续发布 `/cmd_vel_nav`。`control_mux.py` 按显式 `nav/stop` 命令与人工非零速度仲裁，过期命令输出零速度，人工接管后不会自动回放旧 Nav2 速度。`/emergency_stop=True` 锁存急停，需排查原因后重启控制链路。底盘原有速度看门狗和独立安全看门狗保留。

统一 HTTP 任务入口：`GET /task/request?k=TOKEN&source=test&action=goal&request_id=唯一ID&x=1.0&y=2.0`。`source` 可为 `web/mqtt/voice/test`；`action` 为 `goal/manual/stop`。`manual` 使用 `vx/wz`，`goal` 可附 `map_id`。同一来源和请求 ID 的重复调用不会重复执行；同 ID 不同参数被拒绝。MQTT 与语音适配器尚未实现，只能用该入口模拟验收。现有鉴权 token 与网页共用，不应把带 token 的地址公开。

## 地图地点

`/places/add?name=充电位&x=1.0&y=2.0`、`/places/list`、`/places/go?name=充电位&map_id=...`、`/places/delete?name=充电位`。航点页面每行的“存”按钮可命名地点，地点列表可直接前往或删除。数据持久化到 `04_map/robot_map.places.json`；`map_id` 是该地图 YAML 与 PGM 的 SHA-256 摘要。地图变化后，旧地点文件保留，但读取和导航会被拒绝；请人工核对并迁移坐标。网页本地航点队列遇到新 `map_id` 会清空。

## 电量与状态

底盘每 10 秒查询一次 `AT+BATTERY?`，发布 `/battery`（`sensor_msgs/BatteryState`），网页 `/state` 给出电压、底盘报告的百分比及接收时间。电流方向和容量尚无可靠标定，因此不用于剩余时间估计。百分比与万用表实测对比仍是现场验收项。

## 已完成的离线检查与现场验收

已通过 Python 编译、Bash 语法、ROS launch 参数解析、`base_driver`/`robot_bringup` 构建；纯逻辑检查覆盖手动抢占、过期停车、急停锁存、地图持久化与换图拒绝。下次安全场地重启后，按顺序检查：

1. `ros2 topic info /cmd_vel` 确认底盘只接收安全层的运动速度；紧急零速看门狗允许作为额外发布者。
2. 网页人工低速、单点导航、巡逻相互切换；每次按停止后观测车轮立即停住，旧任务不恢复。
3. 用隔离安全场地测试 `/task/request` 的 `source=test`，再接 MQTT/语音适配器。
4. 保存地点、重启页面、核对同一地图可读；换地图后的旧地点须被拒绝。
5. 记录 `/battery` 电压、底盘百分比并与万用表比对。

P1 软件接线已实现；**实车抢占/停车与电量校验未验收**。P0 的导航到站和连续巡逻现场验收也仍需独立完成。
