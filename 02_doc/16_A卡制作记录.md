# A 卡制作记录（16 · 整机克隆 rootfs）

记录日期：2026-09-23
目的：把当前板卡（toybrick-ubuntu）的整套系统 + RobotCode 克隆到新 SD 卡 **A 卡**（hostname `toybrick-acard`），做成可随时替换启动的系统卡。

关联文档：《TB-RK3588SD_Ubuntu22_rootfs》（那次是从 ubuntu-base **新建**系统，本次是**整机克隆**，
所有调好的东西原样带走，推荐做法）；启动原理见其 §2/§2.5。

---

## 0. 一句话结论

> 板子 U-Boot 在 SPI Flash（板上焊死，与卡无关）→ **换卡只换 rootfs**。
> GPT 单分区 ext4 占满 + fstab 写本卡 UUID，插上就能起（§2.5.1 已实测）。
> 本次用 **rsync 整机克隆**，四步完成，全程板子系统盘 `/dev/mmcblk1` 一个字节不动。

---

## 1. 前提确认（格错卡=丢备份，务必先做）

```bash
lsblk -o NAME,SIZE,TYPE,MODEL,MOUNTPOINT
# 板子系统卡永远是 /dev/mmcblk1（绝对不动）
# USB 读卡器里的目标卡是 /dev/sda（本次 A 卡）
```

**插卡后先只读挂载验指纹**（本次就靠这步发现读卡器里先插的是另一张 Debian 卡）：

```bash
sudo mount -o ro /dev/sda1 /tmp/check && ls /tmp/check/etc/os-release && cat /tmp/check/etc/hostname
sudo umount /tmp/check
# 确认是"可格式化"的那张，再继续
```

## 2. 制作四步（本次实际执行的命令）

### ① 重建文件系统（分区表沿用卡上已有的 GPT，不用重做）

```bash
sudo mkfs.ext4 -F -L toybrick-acard /dev/sda1
blkid /dev/sda1        # 记下新 UUID（本次 = 3efe911d-e218-45c9-8144-23d51e58d0f1）
sudo mkdir -p /mnt/acard && sudo mount /dev/sda1 /mnt/acard
```

### ② rsync 整机克隆（源 = 正在运行的系统）

```bash
sudo rsync -axHAX --numeric-ids \
  --exclude='/dev/*'   --exclude='/proc/*'  --exclude='/sys/*' \
  --exclude='/tmp/*'   --exclude='/run/*'   --exclude='/mnt/*' \
  --exclude='/media/*' --exclude='/lost+found' \
  --exclude='/var/cache/apt/archives/*' \
  --exclude='/var/log/*' \
  --exclude='/home/toybrick/.ros' \
  / /mnt/acard/
```

- `-x` 只拷根文件系统本身（其它挂载点不会误入）
- 排除清单省掉 ~1.1G 垃圾（apt 缓存 733M + 旧日志 394M + ROS 日志）
- 实测 7.5G 有效数据，USB2 读卡器 ~17 MB/s，约 10 分钟
- 自动带走：`/opt/ros/humble`、`/lib/librknnrt.so`、`/lib/modules/5.10.160`、
  `~/RobotCode` 全部、`/etc/udev/rules.d/*`（含 `99-dev-cam-npu.rules`）、
  `video/render` 用户组、`.bash_aliases`、SSH host key、`ros2_ws/install`（同架构直接可用）

### ③ 改卡上三处身份信息（fstab 最关键）

```bash
# fstab：换成 A 卡自己的 UUID（不改 = 起不来或错挂）
sudo sed -i 's/UUID=159ead16-1182-4d87-8938-812d6a33fdb0/UUID=3efe911d-e218-45c9-8144-23d51e58d0f1/' /mnt/acard/etc/fstab

# hostname（A 卡取名）
echo "toybrick-acard" | sudo tee /mnt/acard/etc/hostname
```

### ④ 校验、落盘、拔卡

```bash
grep -E '^video|^render' /mnt/acard/etc/group          # video:x:44:toybrick ✓
ls  /mnt/acard/etc/udev/rules.d/                       # 三条规则 ✓
ls  /mnt/acard/opt/ros /mnt/acard/lib/modules          # humble / 5.10.160 ✓
sudo sync && sudo sync && sudo umount /mnt/acard       # 等命令返回再拔卡
```

**换卡启动**：关机 → 拔卡座现卡（即备份）→ 插 A 卡 → 上电。`hostname` 显示
`toybrick-acard` 即成功；想换回旧系统关机对调两卡即可，双向对等。

## 3. 本次踩的坑

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| 1 | 读卡器里的卡差点被当 A 卡格式化 | 上次做完旧卡只读挂载后**没拔**，`/dev/sda` 还是旧卡 | §1 的只读挂载验指纹（`/etc/os-release` + `/etc/hostname`），确认后再动手 |
| 2 | `sed` 改 hosts 没生效，A 卡 `sudo` 会报 resolve 警告 | 本机 `/etc/hosts` 格式特殊：hostname 是**孤立一行**（无 `127.0.1.1` 前缀），常规 sed 模板匹配不上 | `sed 's/^toybrick-ubuntu$/127.0.1.1\ttoybrick-acard/'`——**先 cat 原文件再写正则** |

> 补充：当时还建过 `01_Project/robot_ui → 05_robot_ui` 软链（包名与目录名前缀不符），
> 后来为兼容 `map_viewer` 同级导入改成了 `03_SLAM/robot_ui → ../../01_Project/05_robot_ui`。
> 软链在克隆时原样保留，A 卡可直接 `cd 03_SLAM && python3 -m robot_ui.app`。
