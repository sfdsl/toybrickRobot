## 2. 三个必须先定的决策

### 2.1 定位：继续 slam_toolbox（推荐），amcl 只作备选

| | **slam_toolbox localization（主）** | amcl + map_server（备选） |
|---|---|---|
| 现状 | N1 已真机验收，posegraph 在位 | 未验证 |
| 启动 | 现有 `robotnav` 不变 | 需 map_server 加载 pgm/yaml + `/initialpose` 给定初值 |
| 与 nav2 衔接 | 它自己发 `/map` 和 `map→odom` → **不要再起 map_server**（否则 `/map` 两个发布者打架） | 标准 nav2 组合（`localization_launch.py`） |
| CPU | scan matching 较重 | 更轻 |

**决策**：先走 slam_toolbox，nav2 只起 `navigation_launch.py`（**不含** amcl/map_server/slam）。
若实测 CPU 吃紧或定位不稳，再切 amcl 路线（那时 N1 要重做验收）。

### 2.2 控制器：先 RPP，再对比 DWB

底盘**支持 vx/vy/wz（麦轮）**，但 `/odom` 是**差速积分**（只有左右轮编码器）——横移时里程计不可信，
所以 **nav2 必须配成差速模型，绝不能让它发 `vy`**。

- `nav2_regulated_pure_pursuit_controller::RegulatedPurePursuitController`：**与自研纯跟踪同族**，参数少、行为可预测 → **先用它**，方便和自研结果直接对比
- `dwb_core::DWBLocalPlanner`：更成熟，自带障碍评分轨迹打分 → 第二阶段对比
- `mppi_controller`：效果最好但吃 CPU，RK3588 可以跑，放到最后试

> ⚠ **已被实测推翻（P18/P21，见 §9.1）**：RPP 已删除，当前 `FollowPath` =
> **RotationShimController 包 MPPI**（DWB 整套保留为 `FollowPathDWB` 备用）。
> MPPI 在 RK3588 上 4 Hz 实测跑得动。

### 2.3 规划器：SmacPlanner2D

`nav2_smac_planner/SmacPlanner2D`（8 邻域 A\*，支持代价惩罚）比 Navfn 更接近自研 A\*；
它的 `cost_penalty` 与膨胀代价叠加，正好复现"走宽处"效果。

## 4. 关键配置（照抄即可落地，数值均为本机口径）

### 4.1 基座与代价地图（对齐自研）

```yaml
# local_costmap / global_costmap 共同
robot_radius: 0.12          # 车半宽（与自研一致）
                            # ⚠ 实测：设成 0.15 会报错 —— costmap 算出的内切半径是 0.157，
                            #   大于 inflation_radius 0.15 → "inflation radius smaller than
                            #   inscribed radius"。所以余量只能加在 inflation 那一侧：
                            #   robot_radius 0.12 + inflation 0.15 = 自研"车半宽+0.03 余量" ✓
footprint: "[[0.15,0.15],[0.15,-0.15],[-0.15,-0.15],[-0.15,0.15]]"  # 量完车身后替换 robot_radius
global_frame: map           # global_costmap（local 用 odom）
robot_base_frame: base_link
track_unknown_space: true
unknown_cost_value: 255     # 未知 = 不可通行（与自研同口径；本机未知 59.7%，可达区照样少）
inflation_layer:
  plugin: "nav2_costmap_2d::InflationLayer"
  inflation_radius: 0.15    # ← 对齐自研 --inflation 0.15（硬约束）
  cost_scaling_factor: 8.0  # ← nav2 版"走宽处"：越大越怕贴墙（自研 --prefer-open 3 的量级）
static_layer:
  plugin: "nav2_costmap_2d::StaticLayer"
  map_subscribe_transient_local: true   # slam_toolbox 1Hz 重发 /map，避免反复重建 costmap
obstacle_layer:
  plugin: "nav2_costmap_2d::ObstacleLayer"
  observation_sources: scan
  scan:
    topic: /scan
    data_type: LaserScan
    marking: true
    clearing: true
    # LD14P 只有 ~6 Hz，给它一点"观测保留"，避免障碍在帧间闪烁消失
    observation_persistence: 0.3
```

### 4.2 控制器（RPP，对齐自研纯跟踪）

```yaml
controller_server:
  ros__parameters:
    controller_frequency: 10.0        # 6Hz 雷达不需要 20Hz，省 CPU
    FollowPath:
      plugin: "nav2_regulated_pure_pursuit_controller::RegulatedPurePursuitController"
      desired_linear_vel: 0.15        # 自研直线限速
      lookahead_dist: 0.40            # 自研 L_d
      max_lookahead_dist: 0.90
      rotate_to_heading_angular_vel: 0.4
      use_regulated_linear_velocity_scaling: true   # 转弯降速（自研 0.08~0.10）
      use_cost_regulated_linear_velocity_scaling: true  # 贴障碍降速
      max_vel_x: 0.15
      min_vel_x: 0.05
      max_vel_theta: 0.5
    general_goal_checker:
      plugin: "nav2_controller::SimpleGoalChecker"
      xy_goal_tolerance: 0.15         # ← 自研到位判据（默认 0.25 达不到 0.149 m 的精度）
      yaw_goal_tolerance: 0.175       # ±10°
      stateful: true
```

### 4.3 规划器 + 平滑（对齐自研 A\* 与拐角平滑）

```yaml
planner_server:
  ros__parameters:
    expected_planner_frequency: 1.0
    planner_plugins: ["GridBased"]
    GridBased:
      plugin: "nav2_smac_planner/SmacPlanner2D"
      tolerance: 0.15
      downsample_costmap: false       # 图只有 12.6×15 m，不降采样更准
      cost_penalty: 2.0               # 与 inflation 代价叠加 ≈ 自研 prefer-open
smoother_server:
  ros__parameters:
    smoother_plugins: ["simple_smoother"]
    simple_smoother:
      plugin: "nav2_smoother::SimpleSmoother"
      tolerance: 0.15
      do_refinement: true
```

### 4.4 安全：collision_monitor（替代自研前向扇区）

```yaml
collision_monitor:
  ros__parameters:
    base_frame_id: base_link
    odom_frame_id: odom
    cmd_vel_in_topic: /cmd_vel_nav      # nav2 → monitor → 底盘
    cmd_vel_out_topic: /cmd_vel
    polygons: ["FrontSlow", "FrontStop"]
    FrontSlow:
      type: "polygon"
      points: "[[0.12,0.18],[0.35,0.18],[0.35,-0.18],[0.12,-0.18]]"
      action_type: "slowdown"
      slowdown_ratio: 0.4
      linear_min: 0.05
    FrontStop:
      type: "polygon"
      points: "[[0.12,0.10],[0.22,0.10],[0.22,-0.10],[0.12,-0.10]]"
      action_type: "stop"
```

> 这是自研"±30° 扇区、0.25 m 减速 / 0.15 m 急停"的等价物。
> 链路改成 **nav2 发 `/cmd_vel_nav` → collision_monitor 过滤 → `/cmd_vel`**，底盘侧不用改。

### 4.5 /odom 断流保护（nav2 不管，自己补）

`safety_watchdog.py`（约 60 行）：订阅 `/odom` + `/cmd_vel`，
超过 **1.5 s** 无 `/odom` → ① 发零速度 ② 调 `navigate_to_pose` 的 cancel → 停车退出。
（自研 N5 未做的"拔串口"测试，正好在 nav2 版里补上。）

### 4.6 手机页面桥接（`/goal_pose` → action）

`nav2_goal_bridge.py`：订阅 `/goal_pose`（`PoseStamped`）→ 用 `nav2_simple_commander.BasicNavigator`
发 `goToPose()`；收到新目标自动取消上一个（= 自研的"途中改道"）；提供 `/goal/clear` 等价的 cancel。
**手机网页与 `phone` 别名零改动** ✅

> 多航点巡检：改用 `navigate_through_poses` + `waypoint_follower`（自研没有的能力）。

> nav2 的路径要从 `/plan` 取，所以用这个入口；量距与判定**复用 check_path.py 的函数**，保证同一把尺子。

### 切换判据（满足才把 nav2 设为默认）

| 项 | 门槛 | 自研基准 |
|---|---|---|
| 到达精度 | ≤ **0.15 m** | 0.149~0.150 m |
| 离障碍最近 | ≥ **0.12 m**（`navcheck` 量） | 0.160~0.330 m |
| 窄处占比（<0.35 m） | ≤ **15%** | 开启 prefer-open 后 9%~12% |
| 单次导航 CPU | nav2 + slam_toolbox < **60%**（8 核） | 自研极低 |
| 恢复行为 | 挡路能自恢复，不"卡死转圈" | 停车等待 + 重规划 |

任一项不达标 → **回到自研**，nav2 继续调参，不删旧代码。

## 6. 本机专属风险清单（换 Humble 后新踩/预见的坑）

| # | 风险 | 对策 |
|---|---|---|
| 1 | **nav2 发 `vy`（横移）→ 里程计不可信** | 必须差速模型；controller 参数禁用全向；launch 里不设 `omnidirectional` |
| 2 | **底盘 `/cmd_vel` 0.5 s 看门狗**：nav2 空闲不发指令会触发停车 | 无害（空闲本就该停），但**不要让 `controller_frequency` 低于 2 Hz** |
| 3 | **`/map` 两个发布者**（slam_toolbox + map_server） | 走 slam_toolbox 路线时**不起 map_server**；切 amcl 路线时反过来 |
| 4 | 地图**未知区 59.7%** | `track_unknown_space: true` + `unknown_cost_value: 255`；目标点先用 `navcheck` 挑，别指望 nav2 能救地图质量 |
| 5 | 雷达 **~6 Hz**（慢） | `observation_persistence: 0.3`；`controller_frequency: 10`；速度压在 0.15 m/s |
| 6 | TF 时间戳 / `/odom` 断流（串口假死，08 里踩过） | nav2 对 TF 延迟敏感 → 保留 `safety_watchdog`；`use_sim_time: false` 全场一致 |
| 7 | CPU：RK3588 上 nav2 全套 + slam_toolbox | 降频（controller 10 / planner 1 / local costmap 5）；必要时切 amcl |
| 8 | 自研 phone 页面发的是**话题**，nav2 收 **action** | 桥接节点；否则"点了没反应"会误判成 nav2 坏了 |
| 9 | 参数照抄官方模板 | 官方 `nav2_params.yaml` 是 Turtlebot3 口径（`robot_radius 0.22`、`inflation 0.55`、`use_sim_time: True`、`xy_goal_tolerance 0.25`）→ **必须全改**，尤其 `use_sim_time: False` |
| 10 | **`robot_radius` 必须 < `inflation_radius`**（P0 实测踩到） | costmap 会把 `robot_radius` 算成内切半径 0.157（比设定值大），与 `inflation_radius 0.15` 冲突 → 启动报错。本机正解：**robot_radius 0.12 + inflation 0.15** |
| 11 | 官方 `navigation_launch.py` 的 cmd_vel 重映射是硬编码 | 插不进 `collision_monitor` → 本方案自写 `nav2.launch.py`（controller→`cmd_vel_raw`→smoother→`cmd_vel_nav`→monitor→`cmd_vel`） |
| 12 | **nav2 的 inflation 是软约束，≠ 自研硬膨胀**（P1 实测） | 安全距离 = 膨胀曲线衰减到"致命线"的距离，不是 `inflation_radius`。实测调 `cost_travel_multiplier`(2→8)、`lethal_cost_threshold`(100→76)、`trinary_costmap` **路径完全不变**；只有 `cost_scaling_factor` 有效（8.0→6.0，致命线 0.116→0.155 m）。**⚠ P16 部分推翻**：`lethal_cost_threshold` 直接决定**不可通行线**（`d* = ln(252/thr)/csf`），调它有效且关键——车绕行停驻点站进致命格会 `no valid path`（见 §9.1）。P1 当时"无效"是因为只看路径形状、没看规划成败 |
| 13 | nav2 的**终点吸附比自研激进**（P1 实测） | 目标点贴墙时 nav2 停在离障 **0.110 m**（< 车半宽 0.12），且会被 collision_monitor 拦在 0.15 m → **永远"到不了目标"**。修法：bridge 下发前用自研 `snap_goal_px()` 净化（实测 0.110 → **0.140 m ✓**） |
