# RK3588 YOLOv5 摄像头检测 · 开机自启动教程

适用工程：`rk3588-atk-yolov5_2026/yolov5/cpp`
目标：板子通电/重启后，自动运行目标检测（可选“无界面后台”或“桌面弹窗”两种模式）。

---

## 0. 先确认两件事

| 项目 | 查看命令 | 本机实测 |
|------|----------|----------|
| 摄像头设备节点 | `ls /dev/video*` | USB 摄像头在 `/dev/video0`（不是 `video44`） |
| 桌面用户 / 环境 | `ls /home`、`ls /usr/share/xsessions/` | 用户 `toybrick`，桌面 **GNOME** |
| 是否自动登录 | `grep -i autologin /etc/gdm3/daemon.conf` | `AutomaticLogin = toybrick`（已开启） |

> ⚠️ **摄像头索引是 0，不是 44。** `run.sh` 默认 `44` 是正点原子 MIPI 摄像头序号；本机只有 USB 摄像头，对应 `/dev/video0`。下文所有命令都用 `0`。若以后接 MIPI 摄像头，把 `0` 改成 `44` 即可。

## 1. 方式 A：桌面弹窗自启（本机采用 ✅）

开机后自动进 GNOME 桌面，并弹出带检测框的视频窗口。
**原理**：GNOME 登录后会执行 `~/.config/autostart/` 下的 `.desktop`，进程继承桌面的 `DISPLAY`，于是 `main.cc` 里 `use_gui = (getenv("DISPLAY") != nullptr)` 为真，走 `imshow("out", ...)` 弹窗分支。

### 1-1 包装脚本（等摄像头就绪再启动）

文件：`rk3588-atk-yolov5_2026/yolov5/cpp/autostart_yolov5.sh`

```bash
#!/bin/bash
# 桌面开机自启包装脚本：等摄像头设备就绪后再启动 YOLOv5 检测窗口
# 由 GNOME 会话(autostart)调用，自动继承 DISPLAY 等环境变量 -> 走 GUI 窗口模式

SCRIPT_DIR="/userdata/aidemo/rk3588-atk-yolov5_2026/yolov5/cpp"
RUN_SH="$SCRIPT_DIR/run.sh"

# 等 /dev/video0 出现（最多 60s），避免登录瞬间摄像头驱动还没就绪
for i in $(seq 1 60); do
    [ -c /dev/video0 ] && break
    sleep 1
done

# 启动检测（摄像头索引 0 = 当前 USB 摄像头）。GUI 窗口由 run.sh 在 DISPLAY 存在时自动开启
exec /bin/bash "$RUN_SH" 0
```

```bash
chmod +x /userdata/aidemo/rk3588-atk-yolov5_2026/yolov5/cpp/autostart_yolov5.sh
```

### 1-2 桌面自启条目

文件：`/home/toybrick/.config/autostart/rknn-yolov5.desktop`（属主需为登录用户 `toybrick`）

```ini
[Desktop Entry]
Type=Application
Name=RK3588 YOLOv5 Detection
Comment=Start YOLOv5 camera object detection window at desktop login
Exec=/bin/bash /userdata/aidemo/rk3588-atk-yolov5_2026/yolov5/cpp/autostart_yolov5.sh
Terminal=false
X-GNOME-Autostart-enabled=true
Hidden=false
```

### 1-3 释放摄像头（关键！）

如果之前用 systemd 跑过，必须停掉，否则两个进程抢同一个摄像头：

```bash
sudo systemctl stop rknn_yolov5.service
sudo systemctl disable rknn_yolov5.service
```

### 1-4 验证

- **不重启验证**：在本机 GNOME 终端（不是 SSH）执行
  ```bash
  /bin/bash /userdata/aidemo/rk3588-atk-yolov5_2026/yolov5/cpp/autostart_yolov5.sh
  ```
  应立即弹出 `out` 窗口。
- **重启验证**：直接重启板子，进桌面后自动弹窗（前 ~60s 在等摄像头，属正常）。

> **触摸屏关闭窗口（全屏）**：窗口用 OpenCV 的 `WINDOW_FULLSCREEN` **全屏**显示（无标题栏、无系统 X、无任务栏）。画面**右上角有红色 “X” 触摸按钮**，点该区域即退出——点击坐标是图像像素坐标（OpenCV 内部已按全屏显示比例换算），直接判定 `g_btn`（并外扩 20px 容差）。键盘 `ESC` / `q` 也能退出。显示前已做 `RGB→BGR` 转换修正红蓝反色。
> - 全屏无标题栏，故**不使用** `WND_PROP_VISIBLE` 轮询（它会在开机早期 GNOME 会话未就绪时误判窗口不可见、导致自启秒退）；只靠红 X / ESC / q 退出，开机自启稳定。
> - 相关代码在 `main.cc`（`setWindowProperty(WND_PROP_FULLSCREEN, WINDOW_FULLSCREEN)` + `on_mouse` 回调 + 画面上 `draw_rectangle/draw_line` 画的红 X），无需 GTK 依赖。
> - 最大化代码在 `main.cc`（`namedWindow` 时存顶层窗口句柄 `g_win` 并连接 `delete-event`，首帧 `imshow`+`waitKey` 后 `gtk_window_maximize`，用 `HAVE_GTK_MAXIMIZE` 宏包裹，交叉编译不受影响），GTK 依赖见 `CMakeLists.txt` 的 `gtk+-3.0`。系统 X 关闭检测采用 `WND_PROP_VISIBLE` 轮询 + **“确认窗口可见过一次后、连续 30 帧不可见才判定关闭”** 的双重保护，避免开机早期 GNOME 会话未就绪、窗口未 map 时属性瞬态返回 -1 导致自启误退出。
> - **避免“关了又开 / 重复窗口”**：`run.sh` 加了单实例锁（`flock /tmp/rknn_yolov5_cam.lock`），防止 GNOME 登录自启与手动点图标/脚本重复启动导致出现两个窗口。`/etc/systemd/system/rknn_yolov5.service` 当前为 `disabled`，不会自动拉起，无需处理。

#### (d) 钉到左侧 Dash 收藏夹（推荐 ✅）

标准 GNOME 行为，无需扩展。把启动器写进 `favorite-apps`：

```bash
APP=rknn-yolov5.desktop
CUR=$(dconf read /org/gnome/shell/favorite-apps)
if echo "$CUR" | grep -q "'$APP'"; then
  echo "already in favorites"
else
  if [ -z "$CUR" ] || [ "$CUR" = "@as []" ]; then
    NEW="['$APP']"
  else
    NEW=$(echo "$CUR" | sed "s/]$/, '$APP']/")
  fi
  dconf write /org/gnome/shell/favorite-apps "$NEW"
fi
```

写入后**注销重登或重启 GNOME**，左侧坞里就有一个蓝色摄像头图标，单击即启动。

## 2. 方式 B：systemd 后台无界面自启（备选）

开机后在后台运行，**不弹窗**，检测结果/ FPS 全部写进 `journal`，用 `journalctl` 查看。适合无显示器、只想要“自动跑起来”的场景。

### 2-1 服务文件

文件：`/etc/systemd/system/rknn_yolov5.service`

```ini
[Unit]
Description=RK3588 YOLOv5 Camera Object Detection
# 只等本地文件系统挂载好即可；摄像头就绪由 ExecStartPre 的 sleep 兜底
After=local-fs.target

[Service]
Type=simple
ExecStartPre=/bin/sleep 10
ExecStart=/bin/bash /userdata/aidemo/rk3588-atk-yolov5_2026/yolov5/cpp/run.sh 0
WorkingDirectory=/userdata/aidemo/rk3588-atk-yolov5_2026/yolov5/cpp
Restart=on-failure
RestartSec=5
TimeoutStopSec=10
StandardOutput=journal
StandardError=journal

[Install]
WantedBy=multi-user.target
```

> ❗ **务必避免的反模式**：不要写 `After=multi-user.target` 同时 `WantedBy=multi-user.target`。
> 一个单元既被 `multi-user.target` 拉起、又被要求排在它之后，引导事务会直接把它剔除——
> 表现就是 `systemctl is-enabled` 显示 `enabled`，但**开机根本不启动、`journalctl` 全空**。本文件已更正为 `After=local-fs.target`。

### 2-2 安装与启用

```bash
sudo cp /userdata/aidemo/rk3588-atk-yolov5_2026/yolov5/cpp/rknn_yolov5.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable rknn_yolov5.service
sudo systemctl start rknn_yolov5.service        # 立即启动验证
sudo systemctl status rknn_yolov5.service       # 应显示 active (running)
sudo journalctl -u rknn_yolov5.service -f       # 实时看检测框 / FPS
```

## 3. 两种模式二选一

| 模式 | 有窗口 | 需显示器 | 适用 |
|------|--------|----------|------|
| A 桌面 autostart | ✅ 弹窗 | 需 GNOME 桌面 | 想直接在 HDMI 上看画面 |
| B systemd 后台 | ❌ 仅日志 | 不需要 | 无界面 / 服务器式运行 |

**两者不能同时开**，否则争抢 `/dev/video0`。本机已选定 **方式 A**，方式 B 的服务已 `disable` 备用。

## 5. 排错速查

| 现象 | 原因 | 解决 |
|------|------|------|
| 开机后 `journalctl` 无任何日志、服务 `inactive (dead)` | systemd `After`/`Wants` 指向同一 target 冲突（见 2-1） | 改用 `After=local-fs.target` |
| `Cannot identify device '/dev/video44'` | 摄像头不是 44，本机是 USB 在 `video0` | 启动参数用 `0` |
| 开机后窗口没出、但 `journalctl` 有检测输出 | 跑了**无界面**模式，本就不会弹窗 | 改用方式 A（桌面 autostart） |
| `Failed to open the camera` 反复重启 | 摄像头被另一个进程占用 | 确保只运行一个实例（停掉另一个模式） |
| `librga: Failed to call RockChipRga ... failed to get scheduler` | 板子 RGA 驱动未初始化好 | 代码已自动回退 CPU，检测照常出、仅稍慢；属内核/驱动层问题 |
| 弹窗黑屏 / 无窗口 | OpenCV GUI 后端缺失 | 本机已链接 `libgtk-3`，正常；若换环境需装 `libgtk-3-0` |

## 6. 性能参考（YOLOv5s @ 640×640 INT8）

| 阶段 | 耗时 | 说明 |
|------|------|------|
| pre（letterbox） | ~3–6 ms | RGA 硬件加速（失败回退 CPU） |
| npu（rknn_run） | ~21–23 ms | 帧率上限瓶颈，由模型决定 |
| post（后处理+画框） | ~0.5 ms | 已开 `-O2` 优化 |
| 整体 | ~30–37 FPS | 想再快需换 416/320 输入或 YOLOv5n |
