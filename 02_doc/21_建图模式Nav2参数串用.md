# 建图模式 Nav2 动作服务一直等待（2026-10-20）

现场命令为 `robot --nav2 --ekf`。网页发目标后桥接器反复提示 `NavigateToPose action server not available`。故障启动日志已保存到 `logs/backups/nav2_params_scope_20261020_2218/nav2_failure.log`。

日志在目标发送之前已经报错：

```text
nav2 启动：参数=.../slam_toolbox/config/mapper_params_online_async.yaml
Couldn't load critics! ... No critics defined for FollowPath
Failed to change state for node: controller_server
Failed to bring up all requested nodes. Aborting bringup.
```

原因是 `online_async_launch.py` 与 `nav2.launch.py` 都声明通用参数名 `params_file`。原 bringup 直接 include 两者，建图配置留在共用上下文中，Nav2 的默认参数声明没有覆盖它。控制器没有读到 MPPI 及 critics 配置，退到缺省 DWB 后配置失败；Nav2 生命周期管理器随之停止启动，动作服务一直不可用。定位模式的 slam launch 直接使用固定路径，因此这处问题主要由建图模式触发。

修复后的 bringup 用 `GroupAction(scoped=True)` 隔离各子 launch，并以独立的 `nav2_params_file` 显式传给 Nav2 的 `params_file`，默认指向 `robot_bringup/params/nav2_params.yaml`。桥接器等待动作服务限定为 2 秒；目标响应限定为 5 秒，取消等待限定为 1 秒，服务异常时给出明确错误和停止命令。

验证采用不启动任何子进程的完整 launch 展开：旧版可复现 controller_server 读到 SLAM YAML 的断言失败；修复版在 mapping/localization 两种模式下均读取正确的 SLAM 与 Nav2 参数，并检查实际生成的 Nav2 配置为 MPPI。另在独立 ROS 域验证动作服务缺失时约 2.01 秒返回失败，模拟接受目标及取消路径通过。包构建与 Python 编译通过。本次没有启动底盘或发送实车目标。

下次在安全区域启动 `robot --nav2 --ekf`，启动横幅中的 Nav2 参数应以 `robot_bringup/params/nav2_params.yaml` 结尾；导航生命周期管理器应显示 `Managed nodes are active`。确认 `ros2 lifecycle get /bt_navigator` 为 `active` 后再测试目标。
