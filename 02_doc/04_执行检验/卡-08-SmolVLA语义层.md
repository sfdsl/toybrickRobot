## 一、小需求

| 项目 | 填写内容 |
|------|---------|
| **目标** | 用 SmolVLA（视觉—语言—动作模型）增强语义理解能力：看懂摄像头画面、听懂语音指令，输出高层目标点或有限动作原语，经行为树校验后由 Nav2 执行。 |
| **输入** | RGB 图像、小车状态（速度、电量、定位协方差）、语言指令。 |
| **输出** | 高层目标点 `(x, y, confidence)` 或有限动作原语（`前进1m`/`停止`/`左转30°`），均为**建议**而非直接控制量。 |
| **业务规则** | VLA 输出必须经理性树校验：置信度阈值 + 可达性校验（激光/代价地图）+ 动作幅度限幅 + 阶段命令白名单，四项全过才下发。 |
| **禁止行为** | **VLA 不得直接写入 `/cmd_vel`**；不得绕过代价地图与激光防碰；不得在无置信度阈值时执行动作；不得让旧动作在模型离线后继续执行。 |
| **边界条件** | 模型服务宕机、置信度低、输出超界、图像异常（过曝/遮挡）、指令歧义。 |
| **验收标准** | 30 次试验中碰撞/越界/误停不超过阈值；输出超界时被裁剪而非直通；模型离线时 600ms 内受控停车；错误指令拒绝率 ≥ 95%。 |
| **风险区域** | **模型输出超界、静默失效、幻觉指令、端侧推理可行性未验证**——本项目最高风险模块。 |

## 二、小计划

### 方案 A：动作空间重映射（推荐，且是唯一合理路径）

- **做法**：SmolVLA 的 32 维动作容器前 2 维填 `[v, ω]`，输出连续动作块后由行为树裁剪为高层原语或目标点。VLA 不直接碰底盘。
- **复杂度**：高。
- **维护成本**：高。
- **风险**：SmolVLA 基础模型训练域为机械臂，差速小车无公开实证，需自有数据微调；端侧 RK3588 推理可行性未验证。
- **依赖**：SmolVLA 模型服务（云端 GPU）、行为树框架。
- **适用场景**：本项目语义层增强。

### 方案 B：云端 API 直接调用

- **做法**：把图像与指令发云端 SmolVLA API，返回动作。
- **复杂度**：中。
- **风险**：延迟 300–800ms，断网不可用；成本随调用量增长。
- **适用场景**：原型验证阶段。

### 方案 C：端侧 RK3588 推理

- **做法**：量化模型在 RK3588 本地推理。
- **复杂度**：高。
- **风险**：未取得 RK3588 端到端实测基准；NPU TOPS 为峰值 INT8 吞吐，不等于端到端 token 吞吐；流匹配迭代与注意力缓存是瓶颈。
- **适用场景**：**不可承诺**，仅作候选验证。

### 选定方案与理由

**选定**：方案 A（架构），原型阶段采用方案 B 的云端调用

**理由**：VLA 与 Nav2 分层解耦，既利用 VLA 的视觉语言理解能力，又不绕过已调好的避障与规划。RK3588 端侧需实测后方可承诺。
