## 一、小需求

| 项目 | 填写内容 |
|------|---------|
| **目标** | 实现 ROS2 话题与 MQTT Broker 之间的双向桥接：将小车状态与遥测数据发布到云端，将云端下发的指令转化为 ROS2 话题。 |
| **输入** | ROS2 话题（`/odom`、`/battery`、`/cmd_vel` 等）、MQTT 消息（JSON）。 |
| **输出** | MQTT 主题上的 JSON 消息、ROS2 话题（`/robot/command`）。 |
| **业务规则** | 所有 MQTT 通信必须走 TLS；每个设备使用独立账号与 ACL；消息须含设备 ID、时间戳、序列号。 |
| **禁止行为** | **不得明文传输**；不得暴露数据库账号；不得把 MQTT 指令直接转成 `/cmd_vel`（须经行为树校验）。 |
| **边界条件** | 消息丢失、JSON 字段缺失、时间戳乱序、Broker 不可达、心跳超时。 |
| **验收标准** | 断线自动重连；心跳超时 600ms 内触发停车；消息乱序不影响指令正确性；ACL 越权访问被拒绝。 |
| **风险区域** | **认证与 ACL、TLS 证书、数据库账号、明文传输**——本项目最高风险模块之一。 |

## 二、小计划

### 方案 A：自建桥接节点（推荐）

- **做法**：用 `paho-mqtt` 或 `asyncio-mqtt` 写一个 ROS2 节点，订阅话题并发布到 MQTT，同时订阅 MQTT 指令主题并发布到 ROS2 话题。
- **复杂度**：中，约 200–300 行。
- **维护成本**：中，代码可读。
- **风险**：需自行处理重连、心跳、消息校验。
- **依赖**：`paho-mqtt` 或 `asyncio-mqtt`。
- **适用场景**：需精细控制消息格式与安全策略。

### 方案 B：rosbridge + MQTT 网关

- **做法**：rosbridge 提供 WebSocket，网关转发到 MQTT。
- **复杂度**：中。
- **风险**：链路多一跳（ROS → rosbridge → 网关 → MQTT），延迟增加。
- **适用场景**：需同时支持 Web 端调试。

### 方案 C：Micro-ROS Agent 直连

- **做法**：Micro-ROS 设备直接连 ROS2 DDS。
- **复杂度**：高。
- **风险**：公网 DDS 多播不可达，ESP32 运行 Micro-ROS 资源紧张。
- **适用场景**：局域网内 DDS 可用时。

### 选定方案与理由

**选定**：方案 A

**理由**：链路最短，可控性最高，安全策略（TLS、ACL、心跳、消息校验）全部在自研代码内，便于审查与教学。

## 四、小测试

### 验收条件

- [ ] 断线后 5s 内自动重连并恢复订阅。
- [ ] 心跳超时 600ms 内触发停车。
- [ ] JSON 字段缺失时返回错误，不崩溃。
- [ ] 消息时间戳乱序时不影响指令正确性。
- [ ] ACL 越权访问被拒绝。
- [ ] TLS 配置正确，明文连接被拒绝。

### 测试覆盖

| 类型 | 场景 | 预期 | 通过 |
|------|------|------|------|
| 正常路径 | 发布遥测并下发指令 | 双向正常 | |
| 空值缺失 | 空 payload | 拒绝并记录 | |
| 非法输入 | 非 JSON 内容 | 拒绝并记录 | |
| 边界值 | 超长消息体 | 截断或拒绝 | |
| 重复执行 | 同一指令重复下发 | 不重复执行动作 | |
| 外部失败 | Broker 不可达 | 重连逻辑生效 | |
| 并发 | 高频消息 | 不丢消息或有序丢弃 | |
| 权限 | 越权账号 | 连接被拒 | |
