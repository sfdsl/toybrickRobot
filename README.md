# 小车统一功能路线图

更新：2026-10-19。适用：Toybrick RK3588、Ubuntu 22.04、ROS 2 Humble、LD14P、USB 单目相机、麦轮底盘。

**本文件是功能实施顺序的唯一总索引。**《04_执行检验/卡-01～08》保留各模块需求与验收细节；《10_进阶功能清单》保留 A/B/C 功能创意；《09_使用说明》只写已能日常使用的操作。各文档描述冲突时，以本文件的阶段、当前状态和前置关系为准；具体运行参数以现有代码和实测记录为准。

## 0. 当前基线与状态口径

现有系统使用 **Humble + slam_toolbox + Nav2（SmacPlanner2D、MPPI）**，另保留自研导航作对照。已有四屏网页、单点目标、航点和巡逻代码，以及 `cam_pub → rknn_infer → /detections、/image_det → 网页` 的 YOLO11 链路。因此《10》里 Foxy、无 Nav2 apt、相机还未进入 ROS、NPU 尚未接入、自研 A* 为主线等描述属于早期快照，不再作为新功能的开发前提。

P1 控制仲裁、地点版本持久化、电量话题和统一任务接口已编码构建，待下次启动加载并完成实车验收；详见《18_P1_统一控制与地图数据.md》。`MQTT/语音` 适配器仍属 P3。`P0` 导航实车门槛未因此跳过。`rclpy` 进程当前仍用启动前旧代码。`P1` 不能标记为实车通过。

“有代码”不等于“实车验收”：卡-02 EKF 已按其记录验收，但还留有异常输入测试；卡-03 Nav2 已实现、现场验收未完成；网页多点导航和巡逻仍须完成连续真车测试。最近的 Nav2 到站控制配置调整尚待重新启动后对照实测。卡-01 的“待计划”与现有建图成果不一致，按现有建图和定位链路处理，但地图质量仍可复测。

本路线图用 **已有基础 / 待验收 / 待实现 / 研究候选** 表示状态，不把设计目标写成已完成结果。

## 1. 共用架构：所有会动车的功能先接同一入口

```text
网页 / 航点 / 探索 / 语音 / MQTT / 目标跟随 / VLA 建议
                    │
                    ▼
       统一任务入口：身份、控制权、模式、有效期、地图版本
          ├─ 地点或目标点 ─→ Nav2 action ─→ 速度平滑 ─┐
          └─ 有时限的手动速度 ─→ 速度仲裁 ────────────┤
                                                    ▼
                                      collision_monitor → 底盘
                                        ↑ 独立停止/急停链路

SLAM/定位、雷达、视觉、电量 ─→ 遥测/事件 ─→ 网页、MQTT、数据库、大屏
```

当前网页 `ModeMgr` 仅覆盖网页内部；网页遥控直接发 `/cmd_vel`，Nav2 路径经过 `collision_monitor`。这是后续接入新控制源前需要改造的边界。统一入口应保证同一时刻只有一个运动任务，优先级至少为：**硬件急停/停止 > 人工接管 > 自动任务**；切换时取消旧 Nav2 action、清空旧速度命令，再授予新控制权。手动、语音和跟随的速度也须进入同一安全出口，不直接给底盘。

MQTT 的 600 ms 心跳停车只作用于**正在持有远程控制权的命令租约**；不能因为云端掉线就无条件打断本地离线语音或已获准的自主任务。具体断网后继续还是停车由任务启动时的策略决定，急停始终本地有效。大模型与 VLA 只可提出地点、任务或有限动作建议；实际目标要经地点表、地图可达性和控制权检查。

地图和历史数据统一使用 `map_id/map_version + map 坐标系 + 时间戳`。建图、定位各自只保留一个 `/map` 和一条 `map→odom`；EKF 与底盘也只能有一个 `odom→base_link` 发布者。重建地图后，地点、禁行区、轨迹和语义标注必须标明所属地图版本，不能直接套用旧坐标。

## 2. 分阶段实施与放行条件

| 阶段 | 先做什么 | 覆盖原计划 | 放行条件 |
|---|---|---|---|
| **P0 稳定基础导航**（现在） | 固定一套启动配置；复测定位/TF、到站速度与摆头；实车跑单点、三点巡逻两圈和障碍物；验证停止、雷达/里程计断流及控制权切换；录可回放的 rosbag。 | 卡-01/02/03；A1/A2/A7；B2 的基线 | 卡-03 的 5 点导航成功率、窄道与防撞验收有记录；三点两圈不中断或明确失败原因；停车与异常链路实测通过。未过门槛不叠加新运动功能。 |
| **P1 统一控制与地图数据** | 把网页以外的控制源也纳入任务入口；让手动速度经过共享安全链；明确停止/抢占/超时语义；做地点命名、地图版本和基础电量/状态；保留一键录包。 | 卡-04/05/08 的公共前置；A3/A7/A8/A9；C5 的最小仿真 | 网页、测试 MQTT/语音命令互相抢占时底盘只有一个有效速度源；停止优先；地点在重启后仍能按同一地图找到；电量读数与实测对比。 |
| **P2 地图与自主能力** | 在建图模式运行 Nav2 前沿探索；导航模式复用同一规划/避障栈；地图编辑另存版本，虚拟墙进入规划约束；验证动态行人/移动障碍的绕行或等待。 | B1/B2；A4；C4 的版本准备 | 指定区域探索结束并保存地图；切回定位模式仍可导航；编辑地图不覆盖原图；真实障碍仍由雷达与安全层阻停。 |
| **P3 语音与远程入口** | 先建 MQTT 遥测/任务桥；浏览器语音做交互原型；ESP32-S3 离线命令走本地链路，小智在线指令经适配器转成有限意图；外网监控使用同一鉴权与任务入口。 | 卡-04/05；A6；C2 | 断网时本地“停止”有效；在线和离线重复命令不重复执行；远程掉线时按所属控制租约停车；MQTT 重连、鉴权和乱序测试通过。ESP32 板型、Flash/PSRAM、麦克风及固件集成须先确认。 |
| **P4 感知与数据展示** | 复用已有 YOLO11；标定相机与雷达外参、目标测距；在此基础上分别做目标跟随、语义标注、ArUco 精停；遥测再接数字孪生和轨迹库。 | 卡-06/07；A5；B3/B4/B6 | 相机标定、距离误差和时间同步有数据；目标丢失自动停止；语义点关联地图版本；大屏的 30 fps 是渲染帧率，数据断流须显示过期；历史轨迹可按地图版本回放。 |
| **P5 运行维护与新硬件** | 先有 B4 停靠实测，再加充电桩做回充；长期建图做地图版本迁移；状态灯、屏和按键可在 P1 后并行。 | B5；C4；A8/A9 的扩展 | 回充验收以接触和充电电流为准；长期建图跨日无明显重影且旧地点可迁移；硬件停止按键不依赖网络。 |
| **P6 研究扩展** | 有明确研究问题时再做伪 3D、第二台车、多机地图、SmolVLA。VLA 先离线评估和受控实验，不作为基础导航或语音的依赖。 | C1/C3；卡-08；C5 高保真扩展 | 另列数据集、算力/硬件预算、基线、失败回退与实车验收；达不到门槛可独立搁置，不影响主线。 |

阶段可在满足前置条件后并行：纯展示/入库不必等待 ESP32；离线语音不必等待云端 MQTT；B4 的标定可与 P3 并行。**P0 和 P1 的运动安全接口是 B1/B3/B5/卡-08 的共同前置。**

## 3. 原功能清单归位

| 原编号 | 统一路线中的位置 | 当前判断 |
|---|---|---|
| A1 手机点图、A2 多点巡逻 | P0 | 已有网页与动作链，仍需连续实车验收；不另造 `phone_teleop.py + goal_nav.py` 主线。 |
| A3 地点命名 | P1 | 增加持久化地点表，复用现有目标入口；与 B6 自动语义标注分层。 |
| A4 地图编辑 | P2 | 生成新地图版本；“擦假障碍”不关闭实时雷达安全检查。 |
| A5 NPU 视觉 | 已有基础，P4 扩展 | `cam_pub`、`rknn_infer`、检测画面已具备；相机雷达融合尚待标定。 |
| A6 浏览器语音 | P3 原型 | 与 ESP32 离线语音共享意图入口；浏览器语音不作为断网能力验收。 |
| A7 rosbag | P0/P1 | 启动脚本已有录包选项；补上导航、控制权和故障事件的复盘口径。 |
| A8 灯/屏/按键、A9 电量/温度 | P1，P5 扩展 | 用现有电源板/底盘接口前先核对接线、权限、校准；充电功能另需桩。 |
| B1 前沿探索、B2 动态避障 | P2；B2 基线在 P0 | 直接复用 Nav2，不再并行实现第二套 A*+DWA 主控制器。 |
| B3 目标跟随 | P4 | 单目框宽不足以保证距离；需激光关联/可靠测距和目标丢失停车。 |
| B4 ArUco 停靠 | P4 | 需相机内参、安装外参及近距实测；厘米级是验收目标而非现成精度。 |
| B5 自动回充 | P5 | 依赖 B4 和充电桩、触点/电流检测；现有小车不能仅靠软件完成。 |
| B6 识别结果上图 | P4 | 区分静态地点和会移动的检测目标，记录置信度与地图版本。 |
| C1 伪 3D、C3 多机 | P6 | 分别需要俯仰机构/深度相机、第二台车。 |
| C2 外网监控 | P3 | 复用卡-04 的遥测与鉴权，不开放直接底盘速度入口。 |
| C4 多日建图 | P5 | 切图要迁移地点、轨迹和禁行区；不得让在线定位与建图同时争用 TF。 |
| C5 轻量仿真 | P1 最小版，P6 深化 | 先验证规划/抢占/停车逻辑；“与真车误差 <30%”需标定后才能作为目标。 |

## 4. 执行卡归位与暂不承诺事项

| 卡 | 处理方式 |
|---|---|
| 01 建图 | 现有链路已运行；复核地图质量并更新卡片状态。 |
| 02 EKF | 已验收的基础能力；补完异常输入、IMU 断流后的降级测试。 |
| 03 Nav2 | P0 当前门槛；以现用 MPPI 和真实参数验收，卡名中 TEB 仅为历史方案。 |
| 04 MQTT | P1 定接口、P3 实现；遥测和任务请求分流，云端掉线只影响对应远程控制租约。 |
| 05 ESP32 语音 | P3；浏览器、小智在线和 ESP-SR 离线共用意图词表及执行入口。 |
| 06 数字孪生 | P4 展示端，可先做静态原型；不要求传感器以渲染帧率发布。 |
| 07 PostGIS | P4 历史端，可部署在独立服务器；先定义 `map_id` 和本地坐标系，不把平面米坐标误当经纬度。百万行查询时延须以真实数据与索引实测。 |
| 08 SmolVLA | P6 研究候选。32 维动作容器不意味着直接填 `[v, ω]` 就会驾驶；需要小车数据训练与独立评估。无论结果如何都不直接写 `/cmd_vel`。 |

## 5. 下一步的具体任务

1. 按 P0 在同一张地图、同一组目标点复测 Nav2 到站和网页三点两圈巡逻，记录成功率、总时长、到站末段速度/角速度、TF 新鲜度及失败原因。
2. 把停止、网页遥控、Nav2、未来语音/MQTT 的控制权和速度链路画成当前实际连线图，再确定 P1 的单一任务入口与安全速度出口。保留现有急停和看门狗。
3. 定义地图版本、地点、任务和遥测的最小数据格式；之后再开始 B1 探索、语音或目标跟随。
