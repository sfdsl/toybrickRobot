## 2. 架构

```
/dev/video0 ──► camera_node（自写 ~40 行：cv2 读帧 → sensor_msgs/Image）
                    │ /image_raw（640×480，15 FPS，BGR8）
                    ▼
              rknn_infer_node（NPU 推理）
                    │  RKNNLite(runtime) + yolov5s.rknn
                    │  预处理 resize/letterbox → infer → 后处理 NMS
                    ▼
              /detections（Float32MultiArray：[n, cls, conf, x1, y1, x2, y2]）
                    │
        ┌───────────┼─────────────────┐
        ▼           ▼                 ▼
  手机 HUD      雷达融合(可选)      导航联动(可选)
 (render_loop   camera_lidar_view   警示话题 / B3 跟随
  画框叠加)     角度映射 → "人@2.1m/−15°"
```

**设计决策**（沿用《10》A5 已定口径）：
1. **相机节点自写 ~40 行**，不引入 `usb_cam`（省一个 apt 依赖与格式适配）
2. **消息用 `Float32MultiArray`**，不引入 `vision_msgs`（Humble 无此包）；布局 `[N, 6]`：
   `cls, conf, x1, y1, x2, y2`（像素坐标），首帧前 N 用 `layout.dim` 携带
3. **推理独立成节点**，不做在 camera_node 里——相机 30 FPS 与推理 15 FPS 解耦，
   掉帧不阻塞采集
4. **HUD 叠加走 render_loop**：`phone_teleop` 的渲染线程已经在画 origin/goal/航点，
   detections 画框是同一模式（`detections` → 全局缓存 → render 取用）

## 4. 阶段 P1：相机节点（`ros2_ws/src/cam_pub`）

**4.1 先探测相机能力**（决定采集格式——YUYV 未压缩高带宽，MJPG 需解码但帧率高）：
```bash
sudo apt install v4l-utils
v4l2-ctl -d /dev/video0 --list-formats-ext | head -30
```
优先选 **MJPG 640×480@30**（USB 带宽小，cv2 解码 CPU 可承受）；
只有 YUYV 就 640×480@15（YUYV 640×480×2B×15 ≈ 9 MB/s，本机回环可承受）。

**4.2 节点骨架**（`cam_pub.py`，纯 rclpy + cv2，`sensor_msgs/Image`）：
```python
rclpy.init(); node = rclpy.create_node('cam_pub')
pub = node.create_publisher(Image, 'image_raw', 1)   # depth=1：只留最新帧，天然丢帧不积压
cap = cv2.VideoCapture(0)
cap.set(cv2.CAP_PROP_FOURCC, cv2.VideoWriter_fourcc(*'MJPG'))
cap.set(cv2.CAP_PROP_FRAME_WIDTH, 640); cap.set(cv2.CAP_PROP_FRAME_HEIGHT, 480)
cap.set(cv2.CAP_PROP_FPS, 30)
timer = node.create_timer(1/15, lambda: pub.publish(bridge.cv2_to_imgmsg(cap.read()[1], 'bgr8')))
```
- `depth=1` QoS：推理节点慢一拍时**丢旧帧**（视觉检测要的是"现在"，不是"历史"）
- 相机**直插主板 USB**（雷达 hub 抖动的教训——相机与雷达抢带宽会互相拖累）

**4.3 验收**：`ros2 topic hz /image_raw` ≥15 Hz 稳定；`/odom` 与 `/scan` 无劣化。

## 5. 阶段 P2：推理节点（`rknn_infer_node`）

**5.1 模型**：yolov5s → rknn（在 **PC** 上用 rknn-toolkit2 转换；板端只跑 lite）。
来源二选一：旧卡 aidemo 例程自带的 .rknn（最快）；或 rknn_model_zoo 的 yolov5s。

**5.2 节点骨架**：
```python
from rknnlite.api import RKNNLite
rk = RKNNLite()
rk.load_rknn(MODEL_PATH)
rk.init_runtime(core_mask=RKNNLite.NPU_CORE_0)     # 单核起步；6TOPS 富余

def on_image(msg):
    frame = bridge.imgmsg_to_cv2(msg, 'bgr8')
    inp = letterbox(frame, 640)                     # 预处理（CPU）
    outs = rk.inference(inputs=[inp])               # NPU 推理
    dets = nms_postprocess(outs, conf_th=0.45)      # 后处理（CPU，纯 numpy）
    pub_detections(dets)                            # Float32MultiArray
    cache_frame_with_dets(frame, dets)              # 给手机 HUD 叠加
```

**5.3 `/detections` 格式**（Float32MultiArray，自定协议写进注释）：
```
dim[0] = N（目标数）
data = [cls, conf, x1, y1, x2, y2] × N   （像素坐标，640×480 基准）
```

**5.4 验收**：端到端 ≥10 FPS（`ros2 topic hz /detections`）；人对镜头举手/挥瓶可识别；
`htop` 看 CPU 占用（预期推理 <1 核，预处理 <0.5 核）。

## 8. 风险清单（本机专属）

| # | 风险 | 对策 |
|---|---|---|
| 1 | **NPU 用户态库缺失**（已实证） | P0 按旧卡搬运 → 官方 release 兜底；搬运后 `ldd librknnrt.so` 查缺依赖 |
| 2 | **runtime 与驱动版本不匹配**（`dmesg` 里的 RKNPU driver 版本 vs librknnrt 版本） | 搬旧卡的库与旧卡驱动同源，天然匹配；官方包则看 release notes 的驱动要求 |
| 3 | **USB 带宽/稳定性**：相机与雷达若同 hub，抖动互相拖累（雷达已两次事故） | 相机直插主板；P1 验收时同时盯 `/scan` 频率不劣化 |
| 4 | **YUYV 带宽**：640×480×2B×30fps ≈ 18 MB/s，USB2.0 紧张 | 优先 MJPG；或降 15 FPS |
| 5 | **CPU 争抢**：导航 4 Hz 控制循环 + slam_toolbox 已在跑；视觉预处理/后处理抢核 | 推理走 NPU；后处理用 numpy 向量化；必要时 `taskset` 绑核（导航绑 4 核、视觉绑 4 核） |
| 6 | **模型转换在 PC**：本机不能转（toolkit2 只有 x86 版） | 需要一台 x86 Linux（或 WSL）装 rknn-toolkit2；只做一次 |
| 7 | **相机自动曝光夜视差/频闪** | 固定场景先锁曝光；夜间识别率下降属预期 |
| 8 | 检测结果**抖动**（目标忽隐忽现）→ HUD/联动闪烁 | 后端加 3 帧滑窗多数表决 + IoU 跟踪（简单卡尔曼即可），P3 再做 |
