# 里程计标定实验方案

适用设备：RK3588（Toybrick）+ 莱斯特麦轮底盘
适用节点：`ros2_ws/src/base_driver`（`chassis_node.py`）
制定日期：2026-09-17
前置条件：真机初验已通过（车轮方向、编码器符号全部正确，见《05_实验记录与结论.md》），
剩余工作为**尺度标定**：`ticks_per_meter`（每米脉冲数）+ `wheel_separation`（轮距）。

---

## 0. 准备工作

- 器材：卷尺（≥ 3m）、胶带（地面标记用）、手机（计时/计算）
- 场地：平整、2~3 米直线空间，尽量在硬质地面（避免地毯导致轮子打滑）
- **串口独占**：实验全程只能有一个程序开 `/dev/ttyCH341USB0`，
  开始前先 Ctrl+C 停掉正在运行的节点，且不要同时开着 bench / 串口助手
- 每进入一个实验前，先 `source` 环境：

```bash
source /opt/ros2-foxy/install/setup.bash
source ~/RobotCode/ros2_ws/install/setup.bash
```

## 实验 B：直线标定 `ticks_per_meter`（约 10 分钟）

**目的**：确定"走 1 米对应多少编码器脉冲"，修正里程计尺度。

**原理**：`debug_enc:=True` 时节点每秒打印一次编码器累计值；
推车一段已知距离，用累计增量除以距离，即得每米脉冲数。

**步骤**：

1. 地面用胶带贴出 **2 米** 直线（起点、终点各贴一条，间距用卷尺量准）
2. 启动节点（带调试参数）：

   ```bash
   ros2 run base_driver chassis_node --ros-args -p debug_enc:=True
   ```

3. 等日志出现最新一条 `ENC 增量/累计：A xx/AAA  B xx/BBB`，
   抄下推车前的累计值：`A0 = ______`，`B0 = ______`
4. 把车摆到起点，车头对准终点方向，**慢慢匀速推车（约 0.3 m/s）沿直线到达 2 米终点**，尽量推直
   - 推车期间节点必须保持运行（编码器"读取即清零"，中途停止会丢数据，实验作废重做）
5. 抄下推车后的累计值：`A1 = ______`，`B1 = ______`
6. 计算：

   ```
   ΔA = A1 − A0 = ______
   ΔB = B1 − B0 = ______
   ticks_per_meter = (ΔA + ΔB) / 2 / 2.0 = ______
   ```

   （`(ΔA+ΔB)/2` 是平均每轮脉冲数，再除以实测距离 2.0 m）

7. **复验**：用新参数重启节点

   ```bash
   ros2 run base_driver chassis_node --ros-args -p ticks_per_meter:=<第6步结果>
   ```

   再推 2 米，另开终端执行
   `timeout 5 ros2 topic echo /odom --no-arr 2>/dev/null | head -35`，
   看 `pose.pose.position.x ≈ 2.0`（误差 ±5% 以内算通过；偏差大则重做本实验）
   （注：本机 ros2cli 0.9.11 不支持 `--once`，用 `head` 截断实现"读一次"）

**详细命令一览（可直接复制）**：

```bash
# ── 终端 1：启动节点（带编码器调试打印） ──
source /opt/ros2-foxy/install/setup.bash
source ~/RobotCode/ros2_ws/install/setup.bash
ros2 run base_driver chassis_node --ros-args -p debug_enc:=True

# 等日志出现最新一条「ENC 增量/累计：A xx/AAA  B xx/BBB」
#   → 抄下推车前：A0 = AAA，B0 = BBB

# ── 推车：从起点沿直线推到 2 米终点（节点保持运行！） ──

# 等又出现一条新日志（1 秒内必有）
#   → 抄下推车后：A1 = AAA，B1 = BBB

# ── 计算 ──
# ticks_per_meter = ((A1-A0) + (B1-B0)) / 2 / 2.0

# ── 复验：终端 1 Ctrl+C 停掉后，换新参数重启 ──
ros2 run base_driver chassis_node --ros-args -p ticks_per_meter:=<上面算出的值>

# ── 终端 2：推车前读一次 ──
source /opt/ros2-foxy/install/setup.bash
source ~/RobotCode/ros2_ws/install/setup.bash
timeout 5 ros2 topic echo /odom --no-arr 2>/dev/null | head -35        # 记 position.x = x0（刚启动应为 0）

# ── 再推车 2 米（起点 → 终点） ──

# ── 终端 2：推车后再读一次 ──
timeout 5 ros2 topic echo /odom --no-arr 2>/dev/null | head -35        # 记 position.x = x1
# 校验：x1 - x0 ≈ 2.0（1.9 ~ 2.1 算通过）
```

**关于 /odom 要不要看**：

- **采集数据时（第 3~5 步）不看 /odom**：此时它还是按旧参数（1000）换算的，数字本身就不可信；
  标定依据是 `debug_enc` 打印的**原始编码器计数**（一手数据，不经过参数换算）
- **复验时才看 /odom**（第 7 步）：换上算出的新参数后，/odom 就是"被标定过"的输出，
  用它对照实际距离做验收
- **替代做法**（不想盯日志的话）：不启动 `debug_enc`，直接用 /odom 差值法——
  默认参数启动节点，推 2 米前后各读一次 `position.x` 得 Δx，
  则 `ticks_per_meter = Δx × 1000 / 2.0`
  （例：Δx = 4.0 → ticks_per_meter = 2000；此法够用，但不如编码器法严谨）

## 实验 C：转向标定 `wheel_separation`（约 15 分钟）

**目的**：确定等效转向参数（决定转向角度积分比例）。

> **麦轮重要说明（2026-09-18 实测修正）**：对麦轮底盘，本实验算出的 `sep_calc`
> 是**等效转向参数**（理论 ≈ 轴距+轮距，含转向滑移修正——实测比纯几何值大 14%），
> **不是物理轮距**，实际使用以标定值为准。
> 原理：麦轮原地旋转时每个轮子的滚动线速度 = ω ×（半轴距 + 半轮距），
> 而差速模型假设 ω × 半轮距——两者相差约 2 倍（详见《05_实验记录与结论.md》实验 3）。
> 差速里程计的 `wheel_separation` 参数就填这个等效值，转角才能积分正确。

**前置**：**必须先完成实验 B**（`ticks_per_meter` 未正确时，转向计算会被污染）。

**原理**：原地转一圈，右轮比左轮多滚动的距离 = 轮距 × 2π。
用编码器差值算出这个"差值距离"，除以 2π 即得轮距。

**步骤**：

1. 用实验 A 的轮距作初始参数，启动节点：

   ```bash
   ros2 run base_driver chassis_node --ros-args -p debug_enc:=True -p ticks_per_meter:=<实验B结果> -p wheel_separation:=<实验A结果>
   ```

2. 地面标记车头当前朝向；抄下累计值 `A0 = ______`，`B0 = ______`
3. 另开终端发原地左转指令：

   ```bash
   ros2 topic pub -r 10 /cmd_vel geometry_msgs/msg/Twist "{angular: {z: 0.5}}"
   ```

4. **眼睛盯着车头标记，车体转满一圈（360°，车头回到初始朝向）立即 Ctrl+C**；
   看门狗会在 0.5 秒内自动停车（车轮停稳后再读数据）
5. 抄下累计值 `A1 = ______`，`B1 = ______`，计算：

   ```
   ΔA = A1 − A0 = ______
   ΔB = B1 − B0 = ______
   sep_calc = ((ΔB − ΔA) / ticks_per_meter) / (2 × 3.1416) = ______
   ```

   （结果若为负数说明实际是右转，取绝对值）

6. **对比**：`sep_calc` 与实验 A 的卷尺值 `sep_measured`
   - 两者接近（±10% 以内）→ 采用卷尺值
   - 差异明显 → 采用 `sep_calc`，并重做一遍本实验确认重复性
7. （可选复验）用最终参数重启，原地转半圈（180°），
   `ros2 topic echo /odom --once` 看姿态换算出的 yaw ≈ ±3.14

**数据记录表**：

| 项目 | 符号 | 数值 |
|---|---|---|
| 转前累计 | A0 / B0 | ______ / ______ |
| 转后累计 | A1 / B1 | ______ / ______ |
| 增量 | ΔA / ΔB | ______ / ______ |
| 已知参数 | ticks_per_meter | ______ |
| 实际转角 | θ_real | 2π = 6.2832 |
| **计算结果** | sep_calc | ______ |

> 姿态换算小抄（读 `orientation.z` 和 `orientation.w`）：
> `yaw = 2 × atan2(z, w)`，单位弧度；乘以 57.3 得角度。

## 后续：参数固化（可选）

标定完成后，不必每次都敲 `-p`，可写入参数文件（如 `~/.ros/base_driver.yaml`）：

```yaml
base_driver:
  ros__parameters:
    port: /dev/ttyCH341USB0
    ticks_per_meter: <标定值>
    wheel_separation: <标定值>
```

运行：

```bash
ros2 run base_driver chassis_node --ros-args --params-file ~/.ros/base_driver.yaml
```

## 注意事项与已知局限

1. **串口独占**：节点运行期间任何其他程序都不许开串口，否则数据错乱
2. **编码器"读取即清零"**：推车/转动期间节点必须持续运行，中途 Ctrl+C 则实验作废
3. **推车要稳**：匀速、沿直线；推歪了直接重推（从起点重来并重新记录 A0/B0）
4. **麦轮特性**：驱动板只回 A/B 两路编码器（左右轮），
   横移（`linear.y`）时左右轮反向，差速模型会把侧移误算为自转——
   **横移工况的 `/odom` 不可信**（已知局限），标定和验收时避免横移动作
5. 开环 PWM 没有闭环调速，速度命令与实际速度有偏差，属正常现象；
   标定只保证"位移/角度"的尺度正确，不保证瞬时速度精确
6. 每次实验后把数据填入《05_实验记录与结论.md》归档
