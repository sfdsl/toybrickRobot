## 一、小需求

| 项目 | 填写内容 |
|------|---------|
| **目标** | 用 `robot_localization` 的 EKF 节点融合轮速里程计与 IMU，输出平滑、无跳变的 `odom` 位姿，为建图与导航提供可靠里程计。 |
| **输入** | `/odom`（轮速积分，连续）、`/imu/data`（角速度与线性加速度，高频）、`/tf`。 |
| **输出** | `/odometry/filtered`（EKF 滤波后的里程计）。 |
| **业务规则** | 协方差矩阵必须合理设定；动态参数调优阶段需记录每次参数变更。 |
| **禁止行为** | **不得重复发布 `odom→base_link` 的 TF**——该 TF 只能由 EKF 节点或里程计之一发布，两者不可同时发布。 |
| **边界条件** | IMU 标定未完成（零偏未补偿）、轮速为零时 IMU 噪声放大、协方差发散。 |
| **验收标准** | 直线行驶 5m，滤波后轨迹偏移 < 3cm；原地旋转 360°，累计角度误差 < 5°。 |
| **风险区域** | 协方差发散、TF 冲突。 |

## 二、小计划

### 方案 A：robot_localization EKF（推荐）

- **做法**：扩展卡尔曼滤波，支持任意数量的里程计/IMU/位姿输入。
- **复杂度**：中，参数较多但文档完整。
- **维护成本**：低，ROS2 官方维护。
- **风险**：参数矩阵填错导致协方差爆炸，需用 `rqt` 或话题监控协方差对角线。
- **依赖**：`robot_localization` ROS2 包。
- **适用场景**：差速/阿克曼车，多传感器里程计融合。

### 方案 B：自写互补滤波

- **做法**：低通滤波融合 IMU 与轮速。
- **复杂度**：低，代码量少。
- **风险**：无协方差输出，Nav2 无法利用置信度。
- **适用场景**：资源极度受限或作为对照基线。

### 方案 C：Madgwick/Mahony 姿态滤波 + 独立里程计

- **做法**：仅用 IMU 做姿态估计，轮速独立积分。
- **复杂度**：中。
- **风险**：姿态与位置解耦，无法抑制里程计长期漂移。
- **适用场景**：航向角漂移是主要问题的场景。

### 选定方案与理由

**选定**：方案 A

**理由**：EKF 输出带协方差，Nav2 的代价地图与规划器可直接利用；配置项虽多但可逐组调优，且是 ROS 导航栈的标准做法。

## 四、小测试

### 验收条件

- [ ] 直线 5m 偏移 < 3cm。
- [ ] 原地 360° 累计误差 < 5°。
- [ ] 协方差对角线无 `inf` 或 `nan`。
- [ ] `odom→base_link` TF 仅由一个节点发布。

| 类型 | 场景 | 预期 | 通过 |
|------|------|------|------|
| 正常路径 | 直线 + 旋转组合 | 轨迹平滑 | |
