# 自主导航实验方案（已知地图 → 目标点自主到达）

适用设备：RK3588（Toybrick）+ LD14P 雷达 + 麦轮底盘（`base_driver`）+ 电源板 IMU（定位增强，可选）
目标：在**已建好的地图**中给定一个目标点，小车自主规划路径并到达（路线图"步骤 5"）
制定日期：2026-09-20

**前置条件（均已具备）**：

- 地图：`~/RobotCode/04_map/robot_map.pgm` + `.yaml`（**213×232 格 @0.05 m/px = 10.65 m × 11.6 m**，origin `[-2.66, -7.28]`）
  —— 2026-09-20 12:05/12:10 保存，配合同目录的 `robot_map.posegraph` + `.data`
  （地图统一放 **`~/RobotCode/04_map/`**：2026-09-20 从家目录迁入；新存档用 `savemap` 或手机网页「保存地图」按钮，
   文件名自动带时间戳 `map_YYYYmmdd_HHMMSS.*`，每次都能留档）
- 定位/建图链路：底盘 + 雷达 + slam_toolbox 可正常运行（TF 链 `map→odom→base_link→base_laser` 完整，`/map` 1.00 Hz）
- 电源板 IMU 可用（I2C 裸设备，见 N6；用于定位/航向增强）
- 工具：`drive`（自动行驶）、`phone`（手机网页遥控+看图）、`mapv` / `scanview`（可视化）、`savemap`

## 0. 总体设计

| 环节 | 采用方案 | 现成程度 |
|---|---|---|
| **定位** | slam_toolbox **localization 模式**：加载 `robot_map.posegraph`，持续输出 `map→odom` | 改几行配置即可 |
| **全局规划** | 读 `robot_map.pgm` → 障碍膨胀 → **A\*** → 路径点序列 | 自研（cv2 / numpy 已具备） |
| **控制** | **纯跟踪（pure pursuit）** + `/odom` 到位判定 + `/scan` 前向安全急停 | 自研（复用 `auto_drive.py` 安全层） |
| **目标输入** | `/goal_pose`（`geometry_msgs/PoseStamped`）；可选：手机网页地图点选 | 自研 |
| **航向/里程增强** | 电源板 IMU：角速度 → 航向短期稳定；加速度 → 姿态参考 | 见 N6 |

### 为什么不用 nav2（预检结论，2026-09-20）

- 板上 `/opt/ros2-foxy/install` **没有任何 nav2 包**（只有 `nav_msgs`、`pluginlib` 等基础包）
- **没有配置 ROS apt 源** → 无法 `apt install` → 只能源码构建 `foxy-devel` 分支 nav2
  （包多：`nav2_amcl` / `costmap_2d` / `planner` / `controller` / `bt_navigator` / `dwb_core`…；
  依赖链含 `behaviortree_cpp_v3`（还要 zeromq/cppzmq）、`angles`、`bondcpp`、`diagnostic_updater`、`ompl` 等）
- 本机环境此前已踩过 `nav2_common` 缺失、`tinyxml2` 缺失、`empy` 版本冲突 → 源码构建风险高
  （预计 2~4 小时且不保证一次通过）

**→ 结论**：先用本文档的轻量自研方案出成果；时间富裕再考虑 nav2（主要是要它的代价地图/恢复行为）。

## N1. 地图与定位模式验证（约 30 分钟）

改 `ros2_ws/src/slam_toolbox/config/mapper_params_localization.yaml`（**src 与 install 两份同步**）：

```yaml
mode: localization                # 原 mapping
map_file_name: /home/toybrick/robot_map     # 指向已保存的建图序列（不带扩展名）
map_start_pose: [0.0, 0.0, 0.0]   # 若已知起点在地图中的位姿就填（放在建图起点最省事）
base_frame: base_link             # 原 base_footprint 在本机不存在（同 04 方案的适配）
map_update_interval: 1.0          # 同 04 方案（默认 5.0 太慢）
```

```bash
source ~/.bash_aliases
ros2 launch slam_toolbox localization_launch.py     # 另开：car / lidar 照常
mapv                                                # 看车是否稳定贴在图上
```

**验收**：① `mapv` 里初始位置与实际相符；② 推着车走一圈，车标在地图上连续跟随、不跳变；
③ `ros2 topic hz /map` 有数据（localization 模式下地图是加载来的，不再增长）。

> 注意：**不要同时跑 mapping 模式的实例**（两个节点抢 `map→odom`）；`/scan`、TF 链与建图时一致。

## N2. 全局规划（`goal_nav.py` 的规划部分）

1. 读 `robot_map.pgm` + `.yaml`：像素 254=空闲、0=障碍、205=未知
2. **可通行判据**：空闲格 **且** 距最近障碍 ≥ 膨胀半径（默认 **0.25 m** ≈ 车体半径 0.15 m + 余量；用 `cv2.dilate`）
3. **A\***（8 邻域，直线 1 / 对角 √2 代价）；失败时明确报原因（目标落在障碍/未知/不可达）
4. 路径后处理：抽稀 + 拐角平滑（平滑后必须复查不碰障碍）

**验收**：`--dry-run` 输出"地图叠加路径"的 PNG，肉眼确认不穿墙、不贴死墙角。

## N3. 控制器（纯跟踪 + 安全层）

- **控制律**：取路径上距车 **L_d = 0.4 m** 的前视点 → 曲率 κ = 2·sin(α)/L_d → `wz = v·κ`
- **限速**：直线 ≤ 0.15 m/s；转弯/接近目标时降到 0.08~0.10 m/s（雷达仅 6 Hz，慢是质量的第一要素）
- **安全层**（沿用 `auto_drive.py` 的三层做法）：
  - `/odom` 断流 > 1.5 s（串口假死）→ 立即停车并退出
  - `/scan` 前向 ±30° 扇区内最近距离 < 0.25 m → 减速；< 0.15 m → 急停（等人移开或超时报警）
  - 全程有总超时保护；Ctrl-C 立即发零速度
- **到位判定**：距目标 < **0.15 m** 且朝向误差 < **±10°** → 停车并打印实际误差
- **麦轮约束**：只发 `vx` / `wz`，**不发横移**（横移时差速里程计不可信）

## N6. 电源板 IMU 接入（定位增强，推荐先做）

### N6.1 硬件与访问方式（2026-09-20 实测）

| 项 | 值 |
|---|---|
| 总线 / 从地址 | **`/dev/i2c-6`**，addr **0x69** |
| 器件 | WHO_AM_I（0x75）= **0x67**；6 轴（加速度 + 角速度）+ 温度；**无磁力计** |
| 量程（驱动已配） | 加速度 **±2 g**（÷16384）、角速度 **±250 dps**（1 LSB = 0.0076 dps）、温度（÷128 + 25 °C） |
| 数据寄存器 | temp 0x09，accel 0x0B / 0x0D / 0x0F，gyro 0x11 / 0x13 / 0x15 |
| 参考代码 | `RobotCode/sd_power/imu/`（Rockchip 官方 C 版：`imu.c` + `imu_sample.c`，`make` 后 `./imu_sample`） |
| 内核驱动 | **未绑定**（`i2c-6` 上没有 0x69 的 client）→ 直接按裸设备访问即可，不存在被驱动占用的问题 |

**实测数据（车静止，2026-09-20）**：

- 纯 Python 直读 I2C：**300 帧 / 1.53 s ≈ 196 Hz**（`ioctl(I2C_SLAVE)` + `os.write/os.read`，**零新依赖**）
- 加速度均值 `(0.006, −0.033, −0.982)` g → **芯片 z 轴朝下贴装**；噪声 σ `(0.039, 0.020, 0.022)` g
- 角速度均值 `(−0.37, −0.41, +0.31)` dps → **静止零偏，必须标定扣除**；噪声 σ `(1.08, 0.26, 0.78)` dps
- 温度 32.8 °C（可用于监控板温/散热）
- 误差量级估算：σ≈1 dps 积分 10 s ≈ 0.23°、60 s ≈ 0.55°（**短期很好；长期靠零偏漂移决定**）

### N6.2 注意事项（踩坑清单）

1. **权限**：`/dev/i2c-6` 默认 `crw------- root root`，当前用户不在 i2c 组 → 每次都要 `sudo`。
   建议在 `/etc/udev/rules.d/99-robot.rules`（与串口别名同一文件）加一行：

   ```
   # 电源板 IMU（I2C）
   KERNEL=="i2c-6", MODE="0660", GROUP="dialout"      # toybrick 已在 dialout 组
   ```

   然后 `sudo udevadm control --reload-rules && sudo udevadm trigger` → 之后普通用户可读
2. **没有磁力计 → 没有绝对航向**：陀螺积分必然漂（零偏 0.3 dps 量级 ≈ 每分钟十几度，靠标定可压到几度/分钟）。
   **IMU 只能做短期/动态补充，绝不能替代激光定位**——`map→odom`（slam_toolbox）仍是主定位
3. **零偏必须标定**：每次上电**静置数秒**取平均扣除；温漂存在（记录温度便于复盘）
4. **轴向与符号必须实测确认**：z 轴朝下贴装（accel z ≈ −1 g）；"yaw 用哪个轴"、"符号与车体左正/右正的关系"
   都要实测（原地缓慢转 90°，看哪个轴变化最大、符号如何）
5. **采样率 ≠ 更新率**：纯 Python 可达 ~196 Hz，但传感器 ODR 配置为 100 Hz（寄存器 0x20/0x21 = 0x66），
   实际取 **50~100 Hz** 即可，盲目高频读没有额外信息
6. **I2C 共享总线**：读失败要有重试/降级，**不要卡住控制回路**；不要在实时回路的紧路径里做长阻塞操作
7. **量程边界**：accel ±2 g（急加减速/碰撞会削顶，只作姿态参考）；gyro ±250 dps（本车最大 2 rad/s ≈ 115 dps，够用）
8. **寄存器分 bank**：bank ≠ 0 的寄存器要通过 0x79~0x7E 块访问（见 `imu.c`）；日常读数据用 bank 0 的 0x09~0x15 即可

### N6.3 落地步骤

- **I1** 加 udev 规则（N6.2 第 1 条）→ 免 sudo
- **I2** 写 `imu_driver.py`（ROS 2 节点，纯 Python ioctl，零依赖）：
  100 Hz 发布 `/imu`（`angular_velocity` / `linear_acceleration` / `temperature`）；
  启动静置标定零偏；轴映射、符号、零偏做成参数
- **I3** `auto_drive.py --imu`：`turn()` / `drive()` 改用 IMU 积分角 + 直行纠偏
  （替代现在纯轮式的 `wheel_separation = 0.4085` 经验等效值 → 转向精度直接上一个台阶）
- **I4** （可选，更完整）gyro z 与轮式转角做**互补滤波**融合进 `/odom.theta`，让 SLAM 的转角输入更准；
  或后续源码构建 `robot_localization` 做 EKF 融合
- **I5** 验证实验（归档为《05》实验 6）：
  - 原地转 360° × 3 次：对比 **轮式 / IMU / 激光（map→odom）** 三种角度误差
  - 直线 3 m × 3 次：横向偏差对比
  - 静置 5 min：零偏偏移（dps）与积分漂移（°）

## 注意事项与已知局限

1. **地图质量决定导航上限**：未知区域（灰）**不可通行**（当前地图未知区约 45%）→ 目标点必须在空闲区；
   想让可导航区域更大，先按 04 方案 S5 补扫
2. **无 IMU 时转向依赖经验参数**：麦轮转向滑移使 `wheel_separation=0.4085`（等效值）与实际存在数度误差 → 用 N6 的 IMU 改善
3. **雷达 6 Hz + 近距盲区**：贴墙/近障碍时点云更新慢 → 限速 0.12~0.15 m/s，前向扇区急停
4. **无动态避障/无恢复行为**：静态房间够用；遇人挡路采用"减速→停车→超时报警"而非绕行
5. **里程计 ±5% 尺度误差**：不用于绝对位置决策（以激光定位为准），只用于速度估计/前视点推算
6. **退化场景**：长走廊、大面积玻璃/镜面会使激光匹配退化 → 尽量避开，或降速通过
