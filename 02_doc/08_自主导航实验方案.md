## N0. 操作手册（命令级：从启动到跑完）

> **安全底线**：全程空场、慢速、有人看护；任何时刻 Ctrl-C 立即停车；乱套了先 `robotstop`。
> **同一时刻只能有一个"司机"**：`nav` / `drive` / `phone` 都在发 `/cmd_vel`，同时开会互相抢指令。
> 约定三个终端：**A = 启动/导航**，**B = 发目标点与查数据**，**C = 看地图（可选）**。

### 阶段 0 · 预检查（车不需要动）

```bash
source ~/.bash_aliases
robotcheck        # 设备在不在（/dev/ttyCH341USB0、/dev/LD14P）+ 有没有旧实例在跑
```

判据：出现 `✓ 预检查通过`。若提示"检测到已有实例在运行" → 先 `robotstop` 清干净再来。

### 阶段 1 · 起定位（真机；车要摆在**建图起点**，见 N1）

```bash
robotnav          # 一次起全：底盘 + 雷达 + slam_toolbox(定位模式) + 手机遥控
robotnav --nav    # 再加一样：导航监听（含连续模式）——之后手机点地图即出发，不用另开终端
```

判据（终端 C 或手机）：

```bash
mapv              # 地图上应出现车标，且与实际位置、朝向一致
phone             # 或手机：用启动时打印的地址打开 http://<小车IP>:8080/ 看同一张图
```

- 车标和实际不符（车没摆回起点）→ 见 N1「建图起点」；差一点不必重启，直接告诉它车在哪：

```bash
ros2 topic pub --once /initialpose geometry_msgs/msg/PoseWithCovarianceStamped \
  "{header: {frame_id: map}, pose: {pose: {position: {x: 0.5, y: -0.3}, orientation: {w: 1.0}}}}"
```

### 阶段 2 · 先用"不动车"验链路（30 秒，每次真跑前都建议做）

终端 A：

```bash
nav --listen --topic /test_cmd_vel --goal-topic /test_goal_pose
#  速度与目标都走测试话题 → 完全不碰真机
```

终端 B：

```bash
ros2 topic pub --once /test_goal_pose geometry_msgs/msg/PoseStamped \
  "{header: {frame_id: 'map'}, pose: {pose: {position: {x: 2.0, y: 1.5}, orientation: {w: 1.0}}}}"
```

> ⚠ **真机在跑 `nav --listen` 时，任何离线自测都必须加 `--goal-topic`**：默认话题就是 `/goal_pose`，
> 真机那个 `nav` 也在订它 → 你的**测试目标会被真机当成真目标执行**（2026-09-21 实际踩过：车被测试目标带跑，
> 反复做小幅移动）。同理：`--topic`（速度）、`--scan-topic`（雷达——假雷达会干扰真机 SLAM）。

终端 A 应依次打印：`等待定位 → 当前位姿 x=… y=… → 等待 /goal_pose → 收到目标点 (2.00, 1.50) →
规划成功（ok）：路径 X m，N 航点 → 开始导航：…`。看到 `规划成功` 即链路 OK，A 里 Ctrl-C 退出。

### 阶段 3 · 真跑（车会动）

先用离线判据把目标点挑好（挑空闲区、看离墙距离，避免跑起来才发现目标在灰区）：

```bash
navcheck --goal 2.0 1.5        # ✓ 通过 再上车；✗/⚠ 就换个目标点，或调 --inflation（别动 --min-obstacle-cells）
```

**方式 A：命令行给一个目标点（最简单）**

```bash
nav --goal 2.0 1.5             # 去地图坐标 (2.0, 1.5)
nav --goal 2.0 1.5 90          # 到点后车头再转到 90°（地图坐标系）
```

**方式 B：`/goal_pose` 连续下发（手机点哪走哪；一次启动、连续跑）**

```bash
# 终端 A（只需启动一次；到达后它会自己继续等下一个目标）
nav --listen
# 终端 B（每发一次车就换一个目标；行驶中再发 → 立刻改道）
ros2 topic pub --once /goal_pose geometry_msgs/msg/PoseStamped \
  "{header: {frame_id: 'map'}, pose: {pose: {position: {x: -1.5, y: -3.5}, orientation: {w: 1.0}}}}"
```

- **连续模式（2026-09-21 改）**：到达一个点后**不停机**，回到等待状态；手机再点一个就接着去下一个
- **途中改道**：行驶中又点了新点 → 放弃当前路径、立刻改道；**同一个点重复下发会被忽略**（不会反复重启）
- **一条命令起全套**：`robotnav --nav`（定位 + 导航监听），之后手机点地图即出发（等价于上面"终端 A"）
- 实测（假底盘 + 隔离 TF，2026-09-21）：连续两点分别 **6.4 s / 5.3 s** 到位（误差 0.148 / 0.147 m）；
  途中改道、重复下发去重、到点后进程继续运行 —— 均正常
- **手机「回原点」按钮**（2026-09-21 加）：一键把目标设为 **(0, 0) = 建图起点**（到点后车头朝建图开局方向）；
  地图上常驻橙色 `origin` 十字标示原点位置。详见 N4 小节

**方式 C：先看计划再开（最保守）**

```bash
nav --dry-run --start 0 0 --goal 2.0 1.5    # 只规划并出图 04_map/robot_map_path.png，不动车
```

跑的时候盯两处：终端 A 的日志（`偏离路径 → 重新规划` / `前方障碍 → 停车等待` /
`到达目标：距终点 0.0x m`）；终端 C 的 `mapv`（车标是否贴着路径走）。

### 阶段 3b · 安全与异常测试（N5 第 4、5 项；空场、有人看护）

**① 人为挡路**（验证"减速 → 急停 → 重规划"）：

```bash
nav --goal 2.0 1.5 --csv ~/RobotCode/logs/traj_safe_$(date +%m%d_%H%M).csv --stop-near 0.25
```

车走起来后，在它**正前方**放下纸箱/挡板（不要用手或脚试）→ 期望日志：
`前方 0.2xm 有障碍 → 停车等待` → 挡超过 3 s → `前方持续被堵 → 重新规划`。
移开障碍后应继续走（或重规划绕过）。记录：**从放障碍到停车的时间**、有没有重规划。

> 该链路 2026-09-21 已在隔离环境离线验证（假雷达 `/test_scan` + `--stop-near`）：检测 +0.24 s，
> 3.0 s 准点升级为"重新规划"，`--max-replan` 用满后自动退出，全程无失控。

**② 异常处理（两种，建议先做 A）**：

- **A 杀底盘节点**（模拟完全失联，无硬件风险）：另开终端 `pkill -INT -f chassis_node` →
  期望 ≈1.5 s 内出现 `中止：位姿断流超过 1.5s` 并发出零速度（底盘节点退出时自己也会发停止）
- **B 真拔串口**（最贴近实验 4 的"串口假死"）：跑动中拔掉 `/dev/ttyCH341USB0` → 期望同上
  （底盘固件 0.5 s 看门狗也会停电机）
- 两者之后都要：插回线/重启 → `robotstop` → `robotnav` 再继续

记录（N5 第 5 项）：从"拔/杀"到日志出现中止的时间（应 ≤1.5 s）、车是否立即停住。

**归档**：每次跑完把 CSV 叠到地图上，连同统计一起进《05》：

```bash
navplot ~/RobotCode/logs/traj_0921_1130.csv --goal 1.5 2.5
# → 输出同名 _on_map.png（红线=实际轨迹、绿点=起点、蓝点=终点、红十字=目标）
#   并打印：耗时 / 轨迹长 / 平均与最大指令速度 / 最终距目标
```

### 常用参数（`nav --help` 看全量）

| 参数 | 默认 | 什么时候改 |
|---|---|---|
| `--goal X Y [YAW]` | — | 命令行给目标（YAW 单位：度，可选） |
| `--listen` | 关 | 等 `/goal_pose`（可连续发多个点） |
| `--topic` | `/cmd_vel` | 自测用 `/test_cmd_vel`（车不动） |
| `--vmax` / `--wmax` | 0.15 m/s / 0.8 rad/s | 场地小、怕撞 → 试 0.10 / 0.6 |
| `--inflation` | 0.15 | 地图补扫干净后可调 0.20~0.25（更远离墙，但可通行区变小） |
| `--min-obstacle-cells` | **0** | **默认 0 = 什么都不抹**（图上小点是椅腿等**真实障碍**，抹掉＝规划会穿过去）；只有确认是残差才调大 |
| `--tol-xy` / `--tol-yaw` | 0.15 m / 10° | 到点精度要求（本次实测停在 0.150/0.149 m，正好在阈值上；想更准给 0.08） |
| `--wait-pose` | 30 s | 定位刚起/加载大序列慢时加大 |
| `--csv OUT` | 关 | 记录轨迹（t,x,y,yaw,v,w,d_goal），配合 `navplot` 出归档图 |
| `--stop-near` / `--slow-near` | 0.15 / 0.25 m | 前向扇区急停/减速阈值；做"挡路"测试可给 `--stop-near 0.25` 更好观察 |
| `--sector-deg` | 30° | 前向安全扇区半角 |
| `--scan-topic` | `/scan` | 自测改用测试话题（如 `/test_scan`），避免假雷达干扰真机 SLAM |
| `--goal-topic` | `/goal_pose` | **自测必改**（如 `/test_goal_pose`）：真机 `nav --listen` 默认就订在 `/goal_pose`，不改的话**你的测试目标会被真机执行、车真的会开过去** |
| `--smooth-iter` | 2 | 拐角平滑迭代次数（0=关闭）；切不过去的紧拐角会自动保持原样 |
| `--prefer-open` | **3** | "走宽处"偏好强度（**0=纯最短路径**）。椅腿缝里钻很贵，路径会绕开走敞亮处；实测 3 即到位，再大收益递减 |
| `--open-dist` | 0.8 m | 多宽算"宽敞"：离障碍小于它开始加价 |
| `--tf-parent` / `--tf-child` | `map` / `base_link` | 位姿取哪对 TF；**自测专用**（换独立坐标系，避免与真机抢 `map→base_link`） |
| `--dry-run` | 关 | 只规划 + 出路径图 |

### 排障（按现象查）

| 现象 | 先查什么 | 怎么办 |
|---|---|---|
| `✗ 30s 内拿不到 map→base_link` | 定位起了吗 | `ps -ef \| grep slam_toolbox`；没起 → `robotnav`；起了 → `ros2 run tf2_tools view_frames.py` 看 TF 链是否 `map→odom→base_link` |
| `规划失败：目标点落在障碍/未知区` | 目标点在灰区（未知约 45%） | `mapv` 挑空闲区的点；**不要**图省事用 `--allow-unknown` |
| `规划失败：A\* 找不到路径` | 真实障碍（椅腿等）把通道挤窄 | 先用 `navcheck --goal …` 复现；可换目标点，或把挡路的椅子挪开**再重扫**（不要靠 `--min-obstacle-cells` 抹掉椅子） |
| `中止：位姿断流` / 走一半突然停 | 串口假死或定位掉线 | 这是保护动作；查底盘串口与 `robotnav`，重启后再跑 |
| `前方 0.1xm 有障碍 → 停车等待` | 真被挡住 | 移开障碍；挡超过 3 s 它会自己重新规划 |
| 日志正常但车不动 | 指令发到哪了 | 是不是还带着 `--topic /test_cmd_vel` 没换回 `/cmd_vel` |
| 车乱跑 / 停不下来 | — | `robotstop`（或在启动终端 Ctrl-C） |

## N1. 地图与定位模式验证（约 30 分钟）

改 `ros2_ws/src/slam_toolbox/config/mapper_params_localization.yaml`（**src 与 install 两份同步**）：

```yaml
mode: localization                # 原 mapping
map_file_name: /home/toybrick/RobotCode/04_map/robot_map   # 建图序列前缀（不带扩展名；09-21 已随地图迁移更新）
map_start_pose: [0.0, 0.0, 0.0]   # 若已知起点在地图中的位姿就填（放在建图起点最省事）
base_frame: base_link             # 原 base_footprint 在本机不存在（同 04 方案的适配）
map_update_interval: 1.0          # 同 04 方案（默认 5.0 太慢）
```

```bash
source ~/.bash_aliases
robotnav            # 一键：底盘 + 雷达 + 定位模式 SLAM + 手机遥控（= 手起 car/lidar/www 那套）
mapv                # 看车是否稳定贴在图上（也可以直接看手机网页里的地图）
```

**验收**：① `mapv` 里初始位置与实际相符；② 推着车走一圈，车标在地图上连续跟随、不跳变；
③ `ros2 topic hz /map` 有数据（localization 模式下地图是加载来的，不再增长）。

**「建图起点」是什么、怎么找（2026-09-21 补充）**：

`map_start_pose: [0, 0, 0]` 的含义是：**启动时假定车正站在「建图那次开局时车所站的位置」**——
该点即地图坐标系原点 **(0, 0)**，且那一刻**车头方向 = 地图 +x 轴**。所以"回到起点"就是回到
建图开始时车的实际位置与朝向。

本机地图（`04_map/robot_map`，**2026-09-21 11:46 重扫版**：252×301 格 @0.05 m = 12.60 m × 15.05 m，
origin `[-2.047, -10.671]`）中，起点像素为 **col=41, row=88**（图像左上角为 0,0；该格为**空闲**；
标注图 `04_map/robot_map_start.png`：十字 = 位置、箭头 = 当时车头朝向）。以起点为中心量四方向：

| 方向 | 第一处障碍 / 未扫区 |
|---|---|
| 左（−x） | 0.70 m |
| **右（+x，即建图时的车头朝向）** | **6.00 m 无遮挡** |
| 上（+y）/ 下（−y） | 0.45 m / 0.55 m |

> **版本记录**：旧图（213×232，起点 col 53 / row 85）已在 2026-09-21 的重扫中被替换，那套像素数**作废**。
> 换图/重扫后按同样方法重算：`col = (0 − origin_x)/res`，`row` 建议直接用 `gn.world_to_px()`（与 `mapq`/`navcheck` 同源）。

- 像素换算（换新地图需重算）：`col = (0 − origin_x) / res`、`row = (H − 1) − (0 − origin_y) / res`
- 摆车建议：**以后每次建图前在地上贴标记（四轮位置 + 车头箭头）**——这就是"起点"，之后照标记摆最省事；
  启动后在 `mapv` / 手机网页看红色三角是否与真实位置重合
- **不在起点也不必重启**：定位模式订阅 `/initialpose`（见 `slam_toolbox_localization.cpp`），
  可直接告诉它车在哪（x/y 为地图坐标，orientation 为朝向四元数）：

  ```bash
  ros2 topic pub --once /initialpose geometry_msgs/msg/PoseWithCovarianceStamped \
    "{header: {frame_id: map}, pose: {pose: {position: {x: 0.5, y: -0.3}, orientation: {w: 1.0}}}}"
  ```

- 偏差小（几十厘米 / 十几度）时通常无需干预：scan matching 会自己收敛

> 注意：**不要同时跑 mapping 模式的实例**（两个节点抢 `map→odom`）；`/scan`、TF 链与建图时一致。

**N1 实测（2026-09-21）**：验收 ①②③ **均通过**（车摆在建图起点，`mapv`/手机网页里车标与实际相符、
推车跟随连续不跳变、`/map` 有数据）。

## N2. 全局规划（`goal_nav.py` 的规划部分）

1. 读 `robot_map.pgm` + `.yaml`：像素 254=空闲、0=障碍、205=未知
2. **可通行判据**：空闲格 **且** 距最近障碍 ≥ 膨胀半径（当前 **0.15 m** = 车半宽 0.12 m + 余量；
   新图未知 59.7%、椅腿把通道挤窄，0.25 m 下只剩 11.3% 可通行 → 见下方膨胀对比；用 `cv2.dilate`）
3. **A\***（8 邻域，直线 1 / 对角 √2 代价）；失败时明确报原因（目标落在障碍/未知/不可达）
4. 路径后处理：抽稀 + **拐角平滑**（Chaikin 切角 + 逐拐角验收 + 整条复查）——**2026-09-21 完成**：
   每个拐角单独试切，切出的短边若越出可通行区就**只保留该拐角原样**（其余照常圆化）；
   最后整条逐格复查，任何越界则整体回退。实测（起点 (0,0) → 4 个目标）：
   切角成功率 **21/21、57/57、18/20（目标 (2.0,1.5) 有 2 处太紧自动保留）、27/27**；
   离真实障碍距离不变（0.160~0.200 m）；同一目标折线长 3.03 → **2.95 m**，
   \>20° 的折角 **7 → 3 个**（转弯更平顺，减少"停车式急转"）。开关：`--smooth-iter N`（默认 2，0=关闭）

**验收**：`--dry-run` 输出"地图叠加路径"的 PNG，肉眼确认不穿墙、不贴死墙角。

**判据自动化（2026-09-21）**：`check_path.py`（别名 **`navcheck`**）—— N5 第 2 项「路径不穿墙」的机器判据。
复用 `goal_nav.py` 的规划代码（`GoalNav.plan()` / `simplify_path()` / `blocked_mask()`，**与真机同一份代码路径**），
把路径**逐像素**量成到障碍的距离（`cv2.distanceTransform`）。判据必须与规划器**同口径**——否则量的是
它有意绕开的东西（第一版就踩了这个坑：拿原始图黑点当障碍，3 个目标误判"过紧"）：

| 口径 | 含义 | 判据 |
|---|---|---|
| 真实障碍（去噪后、未膨胀） | 车会不会蹭上 | ≥ **0.12 m**（车半宽） |
| 不可通行区（障碍 ∪ 未知） | 有没有出可通行区 | ≥ **`--inflation`**（当前 0.15 m） |
| 被忽略的小障碍 | **信息行**（仅 `--min-obstacle-cells>0` 时出现） | 多为椅腿等**真实障碍**；出现这行说明规划可能从它身上穿过去 |

**实测**（起点 `(0,0)` → 4 个目标，`--inflation 0.15`，**默认 `--min-obstacle-cells 0`：椅腿当真障碍**）：
**3/4 可达**——路径 8.02 m / **不可达**（被真实障碍隔开）/ 3.03 m / 6.62 m，离真实障碍最近 0.160~0.200 m（≥0.12 ✓）；
抽稀+平滑后的最小距离与 A\* 原始链一致（0.180 vs 0.180）→ **平滑不切角**。
对照：把 4 格以下小障碍抹掉（旧默认 4）会变成"4/4 通过、路径 3.00/5.78/3.03/4.39 m"——
**那是把 275 格真实障碍（椅腿）从图上删掉换来的，规划会直接穿过椅子**，不要这么做。

```bash

navcheck --goals "2.5,-1.0; -1.5,-3.5; 2.0,1.5; 3.0,-3.0"   # 批量 → 汇总表
```

品红圈 = 离真实障碍最近处并标注距离）。
**注意：`navcheck` 检查的就是"车实际走的那条折线"**——它与 `follow()` 共用 `follow_px_path()`
（抽稀 + 拐角平滑）。2026-09-21 加上拐角平滑后已重跑本工具：**4/4 仍通过、离障碍距离不变**，
说明"切不过去就保留原拐角"的验收逻辑在真实地图上确实生效（目标 (2.0,1.5) 有 2 处自动保留）。

**"走宽处"偏好（2026-09-21 加，按现场反馈：有点的地方就是障碍，别钻小缝）**：

原 A* 只求**最短路**，只要缝够宽就敢钻（图上那些小点=椅腿，缝里走过去很危险）。现在给 A* 的
每步代价乘一个"离障碍越近越贵"的系数（`clearance_cost()`，用**未膨胀**障碍图做距离变换）：

    代价系数 = 1 + prefer_open × ((open_dist − d)/open_dist)²      （d ≥ open_dist 时 = 1）
    d < 0.35 m（椅腿缝量级）再 ×3 —— 逼它别从缝里钻

与 `--inflation` 的分工：**inflation 是硬约束**（永远不许更近，做不到就换目标点）；
**prefer-open 是软偏好**（不禁止，但很贵）——所以它不会像调大 inflation 那样把可达区吃掉。

扫参数实测（同一张图，起点 (0,0)）：

| `--prefer-open` | 目标 (1.5,2.5) | 目标 (2.0,1.5) | 目标 (3.0,−3.0) |
|---|---|---|---|
| **0（旧：纯最短路）** | 2.97 m，平均 0.245 m，**窄处 92%** | 3.06 m，0.309 m，**61%** | 7.25 m，0.329 m，**62%** |
| **3（新默认）** | 3.20 m，0.483 m，**9%** | 3.80 m，0.470 m，**12%** | 8.37 m，0.569 m，**1%** |
| 6 / 12 / 25 | 3.23 / 3.26 / 3.29 m，窄处 9% / 8% / 8% | 3.83 / 3.86 / 3.88 m，12% / 11% / 11% | 8.66 / 8.72 / 8.93 m，1% / 1% / 1% |

（"窄处" = 离障碍 <0.35 m 的路径占比）→ **3 就到位的**，再往上收益递减、路径更长，所以默认 3。
路径变长 8%~15% 是它的代价；判据 `navcheck` ④ 行现在会打印"平均离障碍 / 窄处占比"，一眼可查。

> 目标点自身贴着椅腿时，`① 最近` 仍会显示 0.16~0.18 m（最后一段必须靠近目标）——
> 这是目标点选得不好，不是路径问题：换一个落在空阔处的点即可。

## N3. 控制器（纯跟踪 + 安全层）

- **控制律**：取路径上距车 **L_d = 0.4 m** 的前视点 → 曲率 κ = 2·sin(α)/L_d → `wz = v·κ`
- **限速**：直线 ≤ 0.15 m/s；转弯/接近目标时降到 0.08~0.10 m/s（雷达仅 6 Hz，慢是质量的第一要素）
- **安全层**（沿用 `auto_drive.py` 的三层做法）：
  - `/odom` 断流 > 1.5 s（串口假死）→ 立即停车并退出
  - `/scan` 前向 ±30° 扇区内最近距离 < 0.25 m → 减速；< 0.15 m → 急停（等人移开或超时报警）
  - 全程有总超时保护；Ctrl-C 立即发零速度
- **到位判定**：距目标 < **0.15 m** 且朝向误差 < **±10°** → 停车并打印实际误差
- **麦轮约束**：只发 `vx` / `wz`，**不发横移**（横移时差速里程计不可信）

**真机启动路径修复 + 离线验证（2026-09-21）**：

`goal_nav.py` 的真导航分支有两处**同类 bug**（循环里只 `spin_once()` 不调 `update_pose()`，
而位姿 `self.pose` / 时间戳 `last_pose_t` **只在 `update_pose()` 里更新**）：

1. 启动"等定位"循环 → `pose` 永远为 `None`，10 s 后必报"✗ 拿不到 map→base_link"——
   即**真导航路径从未真正跑通**（`--dry-run --start` 能跑是因为它直接给位姿赋值，掩盖了这个坑）
2. "等 `/goal_pose`"循环 → `last_pose_t` 持续过期，一收到目标点就误报"中止：位姿断流 >1.5 s"

**已修**：两处循环均持续 `update_pose()`；等待定位的时间改为 `--wait-pose`（默认 30 s，每 5 s 打进度）；
失败时打印三步排查清单（定位起了吗 / TF 链完整吗 / 车在起点吗）。

## N6. 电源板 IMU 接入（定位增强，推荐先做）

### N6.1 硬件与访问方式（2026-09-20 实测）

| 项 | 值 |
|---|---|
| 总线 / 从地址 | **`/dev/i2c-6`**，addr **0x69** |
| 器件 | WHO_AM_I（0x75）= **0x67**；6 轴（加速度 + 角速度）+ 温度；**无磁力计** |
| 量程（驱动已配） | 加速度 **±2 g**（÷16384）、角速度 **±250 dps**（1 LSB = 0.0076 dps）、温度（÷128 + 25 °C） |
| 数据寄存器 | temp 0x09，accel 0x0B / 0x0D / 0x0F，gyro 0x11 / 0x13 / 0x15 |
| 参考代码 | `RobotCode/sd_power/imu/`（Rockchip 官方 C 版：`imu.c` + `imu_sample.c`，`make` 后 `./imu_sample`） |
| 内核驱动 | **未绑定**（`i2c-6` 上没有 0x69 的 client）→ 直接按裸设备访问即可，不存在被驱动占用的问题 |

**实测数据（车静止，2026-09-20）**：

- 纯 Python 直读 I2C：**300 帧 / 1.53 s ≈ 196 Hz**（`ioctl(I2C_SLAVE)` + `os.write/os.read`，**零新依赖**）
- 加速度均值 `(0.006, −0.033, −0.982)` g → **芯片 z 轴朝下贴装**；噪声 σ `(0.039, 0.020, 0.022)` g
- 角速度均值 `(−0.37, −0.41, +0.31)` dps → **静止零偏，必须标定扣除**；噪声 σ `(1.08, 0.26, 0.78)` dps
- 温度 32.8 °C（可用于监控板温/散热）
- 误差量级估算：σ≈1 dps 积分 10 s ≈ 0.23°、60 s ≈ 0.55°（**短期很好；长期靠零偏漂移决定**）

### N6.2 注意事项（踩坑清单）

1. **权限**：`/dev/i2c-6` 默认 `crw------- root root`，当前用户不在 i2c 组 → 每次都要 `sudo`。
   建议在 `/etc/udev/rules.d/99-robot.rules`（与串口别名同一文件）加一行：

   ```
   # 电源板 IMU（I2C）
   KERNEL=="i2c-6", MODE="0660", GROUP="dialout"      # toybrick 已在 dialout 组
   ```

   然后 `sudo udevadm control --reload-rules && sudo udevadm trigger` → 之后普通用户可读
2. **没有磁力计 → 没有绝对航向**：陀螺积分必然漂（零偏 0.3 dps 量级 ≈ 每分钟十几度，靠标定可压到几度/分钟）。
   **IMU 只能做短期/动态补充，绝不能替代激光定位**——`map→odom`（slam_toolbox）仍是主定位
3. **零偏必须标定**：每次上电**静置数秒**取平均扣除；温漂存在（记录温度便于复盘）
4. **轴向与符号必须实测确认**：z 轴朝下贴装（accel z ≈ −1 g）；"yaw 用哪个轴"、"符号与车体左正/右正的关系"
   都要实测（原地缓慢转 90°，看哪个轴变化最大、符号如何）
5. **采样率 ≠ 更新率**：纯 Python 可达 ~196 Hz，但传感器 ODR 配置为 100 Hz（寄存器 0x20/0x21 = 0x66），
   实际取 **50~100 Hz** 即可，盲目高频读没有额外信息
6. **I2C 共享总线**：读失败要有重试/降级，**不要卡住控制回路**；不要在实时回路的紧路径里做长阻塞操作
7. **量程边界**：accel ±2 g（急加减速/碰撞会削顶，只作姿态参考）；gyro ±250 dps（本车最大 2 rad/s ≈ 115 dps，够用）
8. **寄存器分 bank**：bank ≠ 0 的寄存器要通过 0x79~0x7E 块访问（见 `imu.c`）；日常读数据用 bank 0 的 0x09~0x15 即可

### N6.3 落地步骤

- **I1** 加 udev 规则（N6.2 第 1 条）→ 免 sudo
- **I2** 写 `imu_driver.py`（ROS 2 节点，纯 Python ioctl，零依赖）：
  100 Hz 发布 `/imu`（`angular_velocity` / `linear_acceleration` / `temperature`）；
  启动静置标定零偏；轴映射、符号、零偏做成参数
- **I3** `auto_drive.py --imu`：`turn()` / `drive()` 改用 IMU 积分角 + 直行纠偏
  （替代现在纯轮式的 `wheel_separation = 0.4085` 经验等效值 → 转向精度直接上一个台阶）
- **I4** （可选，更完整）gyro z 与轮式转角做**互补滤波**融合进 `/odom.theta`，让 SLAM 的转角输入更准；
  或后续源码构建 `robot_localization` 做 EKF 融合
- **I5** 验证实验（归档为《05》实验 6）：
  - 原地转 360° × 3 次：对比 **轮式 / IMU / 激光（map→odom）** 三种角度误差
  - 直线 3 m × 3 次：横向偏差对比
  - 静置 5 min：零偏偏移（dps）与积分漂移（°）

## 注意事项与已知局限

1. **地图质量决定导航上限**：未知区域（灰）**不可通行**——当前地图（11:46 重扫版）未知 **59.7%**、
   真实小障碍 **270 处 / 403 格**（多为椅腿；`mapq` 2026-09-21 报告），因此 `--inflation` 只能压到 0.15
   （0.15 → 可通行 18.4%、与起点连通 95.2%；0.20 → 14.4%；0.25 → 11.3%）；想让可导航范围更大、
   膨胀调回 0.25，**按 04 方案 S7 重扫**（清场 + 起点标记 + 路线 + `mapq` 量化验收）
2. **无 IMU 时转向依赖经验参数**：麦轮转向滑移使 `wheel_separation=0.4085`（等效值）与实际存在数度误差 → 用 N6 的 IMU 改善
3. **雷达 6 Hz + 近距盲区**：贴墙/近障碍时点云更新慢 → 限速 0.12~0.15 m/s，前向扇区急停
4. **无动态避障/无恢复行为**：静态房间够用；遇人挡路采用"减速→停车→超时报警"而非绕行
5. **里程计 ±5% 尺度误差**：不用于绝对位置决策（以激光定位为准），只用于速度估计/前视点推算
6. **退化场景**：长走廊、大面积玻璃/镜面会使激光匹配退化 → 尽量避开，或降速通过
