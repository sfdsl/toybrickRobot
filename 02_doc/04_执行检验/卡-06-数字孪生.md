## 一、小需求

| 项目 | 填写内容 |
|------|---------|
| **目标** | 用 Vue3 + Three.js 搭建数字孪生大屏，实时展示小车的位姿、雷达扫描扇形、轨迹与状态，支持历史轨迹回放。 |
| **输入** | MQTT 遥测数据（位姿、电量、温度）、遥测数据库查询接口。 |
| **输出** | Web 页面（3D 场景 + 仪表盘 + 告警列表）。 |
| **业务规则** | 实时位姿 ≥ 30fps；万点轨迹不卡顿；雷达扫描扇形实时可视化；深色科技风 UI。 |
| **禁止行为** | **不做地理级大屏**（本项目为局部平面坐标，用不上 Cesium）；不将敏感数据（精确坐标、设备 ID）暴露给未授权用户。 |
| **边界条件** | 数据流中断、点位缺失、坐标系不一致、浏览器兼容。 |
| **验收标准** | 首屏加载 ≤ 3s；实时位姿 ≥ 30fps；万点轨迹流畅；断流时显示最后已知位姿而非卡死。 |
| **风险区域** | 前端鉴权、数据流中断处理、坐标基准一致性。 |

## 二、小计划

### 方案 A：Three.js 自研（推荐）

- **做法**：Vue3 + Three.js + ECharts，自研 3D 场景与数据面板。
- **复杂度**：高，约 120 人天。
- **维护成本**：中。
- **风险**：需自行实现 3D 资产与交互逻辑。
- **依赖**：`three`、`echarts`、`vite`。
- **适用场景**：需定制化视觉效果与品牌风格。

### 方案 B：Foxglove Studio

- **做法**：直接使用 Foxglove Studio 连接 MQTT/ROS2。
- **复杂度**：低。
- **风险**：偏调试工具风格，不适合对外展示大屏。
- **适用场景**：开发期可视化与调试。

### 方案 C：国产低代码平台（图扑/DataV/RayData）

- **做法**：采购商业低代码数字孪生平台。
- **复杂度**：低。
- **风险**：成本高，黑盒，教学适配差。
- **适用场景**：快速交付、有预算。

### 选定方案与理由

**选定**：方案 A（展示大屏）+ 方案 B（开发调试）组合

**理由**：大屏需定制化视觉，自研可控；Foxglove 作为开发期工具降低调试成本。
